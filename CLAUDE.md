# CLAUDE.md

Guidance for Claude Code in this repository.

## What this project is

Self-hosted personal memory + assistant. **`CONCEPT.md` is the target spec**, but the project is being deliberately slimmed against it — external sync, scripting and the sideloaded-plugin ecosystem have been dropped rather than deferred. Projects: `Fishbowl.Core`, `.Data`, `.Api`, `.Host`, `.Mcp` (23 tools), `.Search` (hybrid via `Fishbowl.Data.Search`), `.Bot.Discord` (real bot), `.Scheduler` (event reminders + daily digest). Every project in the solution has code in it. Don't reintroduce a subsystem just because CONCEPT.md still names it — check `docs/slimming-plan.md` first. See `CONTRIBUTING.md` and `docs/superpowers/` for active work.

## Working style — adaptive programming

Find the closest existing solution and **extend it**, don't parallel it. Almost-fits → add overload/option/partial. Genuinely wrong → say so and migrate callers. **Never silently diverge.**

- **HTTP endpoints**: `MapXxxApi()` extensions on `IEndpointRouteBuilder`; resolve the request's scope via `McpContextClaims.Resolve(user)` → `ContextRef` (User or Space), call a repository. Gate with `.RequireScope("read:notes")` etc. — cookie principals bypass scope; Bearer principals must match. Routes under `/api/v1/`.
- **Repositories**: interface in `Fishbowl.Core.Repositories`, impl in `Fishbowl.Data.Repositories`, `AddScoped`. Access via `DatabaseFactory.CreateContextConnection(ctx)` or `CreateSystemConnection()`. The legacy `CreateConnection(userId)` is a `ContextRef.User`-alias kept for cookie callers.
- **Multi-step writes**: `_dbFactory.WithContextTransactionAsync(ctx, async (db, tx, ct) => …)` — see `NoteRepository` for `notes` + `notes_fts` syncing.
- **Schema changes**: add `ApplyVN` in `DatabaseFactory`, bump `PRAGMA user_version`. No EF Core, no migration runner.
- **UI resources/scripts/templates**: `IResourceProvider.GetAsync(path)` only (disk → DB → embedded). Never direct file I/O.
- **Bot clients**: implement `IBotClient` (`Fishbowl.Core.Plugins`) and `AddSingleton<IBotClient, …>` in `Program.cs`. In-tree only — there is no plugin loader and no sideloading. Both scheduler dispatchers fan out over `GetServices<IBotClient>()`.
- **Configuration**: in `system.db` via `ISystemRepository.Get/SetConfigAsync` — never `appsettings.json`, never env vars for runtime config.
- **Frontend backend calls**: `fb.api.notes.list()` etc. — 401s auto-redirect to `/login`. Never `fetch` directly from views/components.

## Architecture

**Dependency direction:** `Host → Api/Bot.Discord/Sync/Scheduler/Scripting → Data/Search → Core`. `Fishbowl.Host` is the **only publish target**; everything else is a library. No cycles, no upward refs.

**One `DatabaseFactory` (singleton), three DB locations:**
- `CreateSystemConnection()` → `fishbowl-data/system.db` — `users`, `user_mappings`, `spaces`, `space_members`, `api_keys`, `system_config`.
- `CreateContextConnection(ContextRef.User(userId))` → `fishbowl-data/users/{userId}/personal.db` — notes, events, todos, tags, notes_fts, vec_notes. Folder-per-context: dropping the whole `users/{userId}/` folder onto another instance moves the user's data atomically (cold import).
- `CreateContextConnection(ContextRef.Space(slug))` → `fishbowl-data/spaces/{spaceId}/space.db` — identical schema to user DBs. Folder is keyed by the space's ULID, not its slug — slug can change (rename) while the folder stays put. `ResolveSpaceAsync` translates slug→id before opening.
- Legacy flat user layout (`users/{id}.db`) auto-migrates to `users/{id}/personal.db` on first open via `MigrateLegacyLayoutIfPresent`. The old `Team` primitive's on-disk layout (`teams/{id}/team.db` and ancient flat `teams/{id}.db`) is renamed wholesale to `spaces/{id}/space.db` by `MigrateTeamsFolderToSpaces`, which runs once at `DatabaseFactory` construction. Both are idempotent and never overwrite a pre-existing new-path file. The `Team`→`Space` table/api_keys rename is system-schema **v8** (`ApplySystemV8`).

Lazy migrations keyed on `PRAGMA user_version` — heads today: user/space DB **v17** (v15 searchable table columns: `rows_fts` + `vec_rows`; v16 resets stored `medium` tile sizes to the default; v17 `app_errors`), system DB **v15** (`users.session_stamp`). Dapper raw SQL; IDs are ULIDs (`Ulid.NewUlid().ToString()`).

**sqlite-vec loaded on every context open.** `SqliteVecLoader.LoadInto(conn)` enables extension loading, calls `LoadExtension("vec0")`, then flips extensions back off. Binaries ship via the `sqlite-vec` NuGet package (v0.1.7-alpha.2 by roji + jeffhandley) — MSBuild drops them under `runtimes/{rid}/native/` automatically. System DB skips this (no vec tables there).

**Two auth schemes, one principal shape.** Cookie (Google OAuth; default) and ApiKey (Bearer `fb_live_…`). On first login, `Program.cs` creates a Fishbowl user, maps `(provider, providerId) → internalUserId`, adds a `fishbowl_user_id` claim. Bearer keys additionally carry `fishbowl_context_type` + `fishbowl_context_id` + one `scope` claim each — `McpContextClaims.Resolve(user)` collapses all of that to a single `ContextRef`. The cookie scheme forwards Bearer requests to ApiKey via `ForwardDefaultSelector`, so `.RequireAuthorization()` is scheme-agnostic. Data isolation is by file boundary, not row filtering.

**OAuth creds in `system.db`, not `appsettings.json`.** `GoogleOptions` binds against `ConfigurationCache` populated at startup by `ConfigurationInitializer : IHostedService`. `POST /api/setup` writes both DB and cache so changes propagate without a restart. Unconfigured options use sentinel `"placeholder"`.

**API/MCP paths return 401, not 302.** `OnRedirectToLogin` is overridden so `/api` and `/mcp` requests get `401` instead of redirect to Google — browsers following the redirect would ruin Bearer/MCP flows. OpenAPI doc at `/api/openapi.json`.

**`/setup` locked after config.** Once `Google:ClientId` is set, `GET /setup` and `POST /api/setup` return `404` (not 302 — harder to bypass). Validates: ClientId ends `.apps.googleusercontent.com`, ClientSecret ≥ 20 chars. No antiforgery (only responds when unconfigured).

**`IResourceProvider` serves the web UI and mods.** Three-tier: disk (`fishbowl-mods/{path}`) → DB (not yet wired) → embedded in `Fishbowl.Data.dll`. **Only embedded hits are memory-cached; disk hits are re-read per request** — "disk file wins" includes edits, so the dev overlay shows changes on F5 without a restart (pinned by `ResourceProviderTests`). `MapFallback` handles non-API paths; unmatched `/api/*` short-circuits to 404 (so it doesn't serve `index.html`). The private `TryOpenEmbeddedStream` helper tries three path forms because MSBuild's `RecursiveDir` produces Windows-style paths on Windows — keep it.

**Discord bot** (`Fishbowl.Bot.Discord`) is the reference `IBotClient` impl, in-tree, not a sideloaded plugin. `DiscordBotHostedService` owns the `DiscordSocketClient` for the host's lifetime — Bulk-overwrites global slash commands on `Ready`, dispatches `SlashCommandExecuted` to `SlashCommandRouter` via a fresh DI scope per invocation, and defers immediately so the 3-second interaction deadline doesn't bite slow paths (`/search` hits the embedding model). DM-only invariant: guild invocations rejected hard at the dispatcher regardless of declared contexts. **Seven commands** in `Commands/*Handler.cs`: `/help`, `/link <code>`, `/unlink`, `/remember`, `/search`, `/recent`, `/upcoming [days]` (calendar events for the next N days, default 7 — times as Discord `<t:…>` markup so they render viewer-local; recurring occurrences pre-expanded by `GetRangeAsync`). `/link` redeems one-shot codes from `IDiscordLinkRepository` (10-min TTL, atomic burn) and writes both `user_mappings (provider="discord", provider_id=<discord_user>)` and `notification_channels` so the DM channel is cached for future sends. `/unlink` is the inverse — deletes the mapping then removes the channel. Token bound from `system.db`'s `Discord:BotToken` via `ConfigurationCache` (same path as Google); empty/`"placeholder"` token → service no-ops with a warning so the host still boots on fresh installs. `/api/setup` accepts and validates `DiscordBotToken` (length + dot-separator shape) and flags `restartRequired: true` because the gateway connection binds at startup. `DiscordBotClient.SendAsync` resolves `notification_channels` → DM channel id → posts; `ReceiveAsync` is deliberately an empty stream (slash-commands not message events). Cold-DM fallback: when the cached channel id misses the gateway cache, looks up the mapped Discord user via `ISystemRepository.GetProviderIdForUserAsync(userId, "discord")`, fetches the user (gateway → REST), opens a fresh DM with `CreateDMChannelAsync`, and re-caches the new channel id so the next send hits the fast path. `SendAsync` is wired live: `Fishbowl.Scheduler.ReminderDispatcher` fires it on event-reminder triggers (see Scheduler section below). Search/recent return titles only — content never leaves the bot (even non-secret notes might be long, or the user might be on screenshare). **Everything the bot, the reminders and the digest say is in the linked user's UI language** (`users.language`; null/automatic and unlinked → English) from one server-side table, `Fishbowl.Core.Util.ChatText` — the same table `SystemMessageNotifier.SubjectFor` reads; command names stay English, their descriptions carry Discord `de` localizations.

**The per-app databases are retired** (space-apps spec, "What goes"). Their tables became space tables (below); `Fishbowl.Core.Apps` keeps only what those reuse — `QueryDsl` (MongoDB-style JSON: `$eq $ne $lt $lte $gt $gte $in $like $isNull $isNotNull` + `$and $or $not`; depth ≤ 5, leaves ≤ 100, `$in` ≤ 50, `limit` ≤ 500; `QueryDslException` → InvalidParams), `AppColumn`/`AppColumnType` as its column shape, `AppJsonParsers`, `SqliteIdentifiers`. Old `apps/<id>/app.db` files stay on disk and in the user/space archives; nothing opens them. Keys with `context_type = 'app'` are refused by `ApiKeyAuthenticationHandler` (else they'd fall back to their owner's personal workspace); the `api_keys` columns `owner_type`/`owner_id` stay for the old rows.

**Scheduler** (`Fishbowl.Scheduler`) runs as `IHostedService` and dispatches event reminders. Ticks every minute with a 30s startup delay; on each tick enumerates personal-context users via `ISystemRepository.ListUserIdsAsync`, opens each user's context DB, runs `IEventRepository.ListDueRemindersAsync(ctx, from, to, notAncient)` which selects events whose `start_at − reminder_minutes` falls in the half-open window. Catch-up window is 6h on first boot so a restart doesn't drop notifications that became due during downtime. The `notAncient` guard (start_at within past 24h) prevents a Monday-morning dispatcher from drowning in long-past triggers. For each due event the dispatcher checks `INotificationChannelRepository.GetAsync(userId, bot.Name)` against each registered `IBotClient` in order; first bot with an enabled channel wins. After a successful `SendAsync` it inserts a `reminders` row with `sent_at` set — that row is the dedupe latch for subsequent ticks (`IReminderRepository.GetSentTriggersAsync`, keyed on `(event_id, scheduled_at)` so each occurrence of a recurring event fires exactly once). **No record when delivery isn't attempted or fails** (channel missing/disabled, `BotDeliveryException`, any send error): every tick also looks back `RetryLookback` (1 h), so a reminder whose send failed — or whose user links Discord a little later — still goes out, once. **RRULE expansion is implemented** via the shared subset parser `Fishbowl.Core.Util.RRule` (FREQ=DAILY/WEEKLY/MONTHLY/YEARLY + INTERVAL + BYDAY-weekly + COUNT/UNTIL): `ListDueRemindersAsync` returns recurring events as per-occurrence `IsRecurringInstance` clones with `StartAt` set to the occurrence (UTC-normalized via `TimeUtil.AsUtc`); a series with a `time_zone` (user schema **v11**, the IANA zone the browser wrote it in) expands in that zone's wall-clock time, so a weekly 18:00 stays 18:00 local across DST — no zone keeps UTC expansion; out-of-subset rules degrade to a single DTSTART occurrence. **Daily digest** (`DailyDigestDispatcher`, same file layout) sends one "here's your day" DM per user per day — today's events + due/overdue todos; opt-in via system config `Digest:Enabled=true` + `Digest:Hour` (server-local, default 7), set with `tools/set-config`; per-user latch is the config key `Digest:LastSent:<userId>`, empty days stay silent but latch, no-channel days don't latch (link-later still delivers same-day). Space-event reminders remain out of scope for MVP — recipient semantics for shared events need a design call. Multi-platform fan-out is the natural next step when the model needs to grow.

**UI is vanilla JS SPA — no framework, no build step, built on the vendored SACRVM APPKIT.** The kit lives verbatim at `Resources/kit/` (release ZIP's `kit/`, `kit/VERSION` says which — currently 2.25.0); **Context is URL-driven** (personal vs space workspace). `#/notes` = personal, `#/space/<slug>/notes` = space. That is the kit's `sac.scope`: `get()` returns `{ type: "root" }` or `{ type: "scoped", slug }` (**`root`/`scoped`, not user/space**), `set({ type: "scoped", slug })` / `set({ type: "root" })` switches, `hashFor()` keeps a link in the active workspace, and `sac:scope-changed` fires on every switch. `fb.api` builds its own paths from `sac.scope.get()` (`api.js` `ctx()`), **not** `sac.scope.endpoint()`: the kit reuses the singular hash prefix for data paths, the REST nesting is plural (`/api/v1/spaces/<slug>/…`). The router strips the space prefix for view lookup (`sac.router.currentResource()`) so one view registration serves both workspaces. Hrefs that should be sticky across contexts (nav items, hub tiles, brand) wrap through `sac.scope.hashFor()`. Switcher: `<sac-menu id="fb-context" slot="context">` inside the shell's `<sac-nav>`, filled by `shell.js`; the context slot is separate from the toolbar slot `fb.toolbar` repaints, so the switcher survives per-view toolbar paints and stays visible on a phone. Its space list reloads on `fb:spaces-changed`, which `fb.api.spaces.create/delete` fire — no view has to tell the shell; a deleted active space falls back to personal. Space context tints the switcher with `--accent-warm` so edits to shared data are unmissable. **Accent colours** (system schema **v9**: `spaces.color`, `users.accent`, plus `users.date_format`) are kit palette slot names (`TagPalette.Slots`, `fb.tags.SLOTS`) or null for the default: a user's accent (profile window, `PATCH /api/v1/me`, cookie-only) replaces `--accent`; a space's colour (spaces settings: the row's colour dot opens a picker dialog; `PATCH /api/v1/spaces/<slug>`, owner-only) takes over the whole UI while that space is active — `--accent` and `--accent-warm` both become it; a space without a colour keeps the personal accent. `shell.js` sets both inline on `:root` so the derived tokens follow; pickers are `<sac-swatch-grid>` via `fb.accents`. `GET /api/v1/me` is an explicit projection — the `User` record's password hash/salt never leave the server. `fb.tags` cache invalidates on `sac:scope-changed`.

**UI smoke test (`Fishbowl.Ui.Tests`)** launches `Fishbowl.Host` as a real subprocess on a free port for Playwright (not `TestServer`). A gated bypass (`FISHBOWL_PLAYWRIGHT_TEST` env + `Testing` environment) injects a test user. **Never set `FISHBOWL_PLAYWRIGHT_TEST` outside that fixture.** Every HTML page carries `PageCsp` (`Fishbowl.Core.Desktop.PageCsp`, set by `PageCspMiddleware` on any `text/html` response without its own policy — the app frame and file content keep theirs): `script-src 'self'` plus the viewer's trusted-app origins, no inline script anywhere (`/login` `/setup` `/pending` load `js/pages/*.js`), `connect-src` open to https and loopback because app installs read a URL typed at runtime. Playwright's polling `WaitForFunctionAsync` evaluates a string, which that policy refuses, so test files that use it open their contexts with `BypassCSP = true` — except `AppsTests`, which tests the app frame's own policy (BypassCSP drops that too) and polls with `EvaluateAsync` instead; `PageCspTests` walks every view under the real policy.

**MCP surface** at `POST /mcp` — JSON-RPC 2.0 over Streamable HTTP, for Bearer keys (a signed-in cookie works too, with full access). Caller mistakes are InvalidParams; an unexpected failure says only "Internal error" (the detail is in the log). Twenty-three tools in `Fishbowl.Mcp.Tools/*` grouped by domain: notes (`search_memory`, `remember`, `get_memory`, `update_memory`, `list_pending`), contacts (`list_contacts`, `find_contact`), events (`list_events`), a space's tables (`table_*`, `row_*` — see Space tables) its app errors (`app_errors`) and the space guide (`space_guide`). Each implements `IMcpTool` with a `RequiredScope`; `ToolRegistry` lists them for `tools/list`. MCP writes pass `NoteSource.Mcp` → `NoteRepository.ApplySourceTags` auto-adds `source:mcp` + `review:pending`. Human edits (cookie path) strip `review:pending` (approval by editing). **Secret-strip invariant:** every note response runs through `SecretStripper.StripNote` — `:::secret`…`:::end` blocks and `content_secret` blobs must never cross the MCP wire. Enforced by `SecretStripInvariantTests`.

**Hybrid search** (`HybridSearchService` in `Fishbowl.Data.Search`) blends sqlite-vec cosine distance (70%) with FTS5 bm25 (30%), each min-max normalised over a 50-candidate pool. `search_memory` tool always calls it; a `degraded: true` flag surfaces on the response when the embedding model isn't ready yet and ranking falls back to FTS-only. FTS query tokens are split on non-alphanumeric then prefix-matched with `AND` — matches how FTS5's default tokenizer indexes hyphenated identifiers. Lives in `Fishbowl.Data.Search` (not `Fishbowl.Search`) because it needs `DatabaseFactory`, and the dep direction forbids `Fishbowl.Search → Fishbowl.Data`; same reason `SqliteVecLoader` is in `Fishbowl.Data`.

**Embeddings:** `MiniLmPipeline` (ONNX Runtime + `Microsoft.ML.Tokenizers.BertTokenizer`) produces 384-dim L2-normalised float vectors for `sentence-transformers/all-MiniLM-L6-v2`. `ModelDownloader` pulls `model.onnx` + `vocab.txt` from HuggingFace on first start, SHA-256-pinned for the LFS-stored model. `EmbeddingInitializer` (`IHostedService`) runs the download detached. Callers on the hot path catch `EmbeddingUnavailableException` and degrade — `NoteRepository.UpsertEmbeddingAsync` logs and continues, `HybridSearchService` flips to FTS-only. `IEmbeddingService` lives in `Fishbowl.Core.Search` so `NoteRepository` can depend on it without a reverse-dep into `Fishbowl.Search`.

**vec_notes sync.** User DB v4 adds `vec_notes` (sqlite-vec virtual table, `FLOAT[384]`). Every `NoteRepository` write embeds `title + stripped content + tags` and writes the blob in the same transaction as `notes` + `notes_fts`. sqlite-vec's vec0 doesn't honour `INSERT OR REPLACE` as a true replace — use **DELETE then INSERT** explicitly. On delete, remove from `vec_notes` BEFORE `notes` (same pattern as `notes_fts`). Text fed to the model is always secret-stripped — a vector built from secret content would let semantic search surface notes on hidden text, violating the same invariant as the MCP wire.

**`POST /api/v1/search/reindex`** (cookie-only) triggers `NoteRepository.ReEmbedAllAsync` — iterates every note in the resolved context, re-runs the embed+DELETE+INSERT in one transaction, returns `{ processed, failed }`. Bearer requests get 403. Mirrored at `/api/v1/spaces/<slug>/search/reindex` for the space workspace. Used on model upgrade or the first time embeddings become available for a pre-existing personal DB.

**`GET /api/v1/search?q=…&limit=…&includePending=…`** is the CONCEPT.md hybrid search over notes: `HybridSearchService` blends sqlite-vec cosine distance with FTS5 bm25 and returns ranked hits + a `degraded: true` flag when the embedding model isn't ready yet. Response shape matches the MCP `search_memory` tool so clients can swap transports. `limit` is clamped to 1–100. Scope: `read:notes`. Space variant at `/api/v1/spaces/<slug>/search`. Notes-only for now; contact-scoped search stays on `/api/v1/contacts/search` until a unified ranker exists.

**Export** (`ExportApi.cs`, cookie-only, Bearer 403 — wholesale export isn't an agent action): `GET /api/v1/export/db` (the context DB via SQLite's online backup API — safe under concurrent writes — inside a ZIP as `personal.db`/`space.db`), `/export/files` (`files/` minus trash and upload temps) and `/export/all` (both; only while files ≤ `Export:CombinedMaxBytes`, default 4 GiB, else 413 and `/export/info` says `combinedAllowed: false`). **Events** live at `/api/v1/events` (personal) and `/api/v1/spaces/<slug>/events` (space). CONCEPT.md § Calendar — "A calendar that belongs to you." `Event` model carries `Title`/`Description`/`StartAt`/`EndAt`/`AllDay`/`RRule`/`Location`/`ReminderMinutes`/`ExternalId`/`ExternalSource` + ULID + created_by + timestamps; the schema is the original `events` table from user DB v1 so no migration was needed. Scopes: `read:events`, `write:events`. List takes optional `?from=…&to=…` as an ISO-8601 half-open range; the repo stores `start_at` as ISO-8601 so lexical string comparison gives the right temporal ordering. **Range reads expand RRULE**: `GetRangeAsync` fans supported rules (see `Fishbowl.Core.Util.RRule`) into per-occurrence clones flagged `IsRecurringInstance` — same `Id` as the master, so a write against an instance's id edits the whole series; out-of-subset rules degrade to the master event; a series expands in its `timeZone` (IANA, sent by the calendar UI, user schema v11) so its wall-clock time holds across DST. A range also returns single events that started before it and still run inside it (multi-day). **All-day events are dates** (user schema **v12**, `Fishbowl.Core.Util.AllDayDates`): `startDate`/`endDate` (`YYYY-MM-DD`, end **exclusive**, iCal style) with `startAt`/`endAt` kept as `<date>T00:00:00Z` anchors for ordering — a date is the same day in every zone. A write with only `allDay` + `startAt` (older clients, agents) gets its dates derived (its `timeZone`'s local date, else the +12 h rule; length = rounded days, at least one); the v12 migration applied the same rules to existing rows (rows without a zone from UTC+13/+14 can land a day early). Range reads match all-day rows on dates with a day of slack each side — callers place them by `startDate` (the calendar UI, the digest and `/upcoming` filter by date); all-day series expand on dates; an all-day reminder fires relative to local midnight of the date in the event's zone (UTC without one). `GetAllAsync`/`GetByIdAsync` stay master-only. JSON gotcha: the `RRule` property serializes as **`rRule`** (Web-defaults camelCase keeps the second capital), the frontend reads/writes that name. `DeleteAsync` cascades the matching `reminders` rows (reminders FK events.id and are ephemeral). Read-only MCP via `list_events` (scope `read:events`) — supports an `upcoming_days` shortcut or an `from`+`to` ISO range (both get expansion via `GetRangeAsync`). Write tools deliberately not exposed: agents scheduling on your calendar has sharper consequences than agents remembering a note. **Calendar UI** at `#/calendar` (`fb-calendar-view.js`): Monday-first month grid + agenda pane; editor swaps in for the grid with title/all-day/start/end/reminder/repeat-preset/location/notes; new events are client-side drafts (POST happens on first save with a title — server rejects empty titles); saves run one after another (`saveEditing` queues on the one in flight), so two quick changes to a new event PUT to the id the first POST returned instead of creating it twice; All day is a kit `<sac-toggle>` (switching it off again brings the times back); all-day events are placed by their `startDate`/`endDate` strings, never through `Date`/UTC (the end field shows the last day, the wire end is exclusive); a multi-day event shows on every day it spans (grid chips and agenda rows after its first day are dimmed continuations without a start time); a busy day's "+N more" is a button opening a kit `<sac-menu>` of all its events; opening a recurring instance loads the master via `GET /events/{id}`; works in both workspaces through `fb.api` (scope-aware paths).

**Contacts** live at `/api/v1/contacts` (personal) and `/api/v1/spaces/<slug>/contacts` (space). CONCEPT.md § Contacts: "Not an address book. A living record of the people who matter." `Contact` model carries `Name`/`Email`/`Phone`/`Notes`/`Archived` + standard ULID + timestamps. Storage: user/space DB schema v5 adds `contacts` + `contacts_fts`. No secret-strip layer — there's no encrypted column on contacts, hence nothing to strip. Scopes: `read:contacts`, `write:contacts`. `ContactRepository` mirrors the `NoteRepository` pattern (FTS rowid mapped via `(SELECT rowid FROM contacts WHERE id = @Id)`; delete FTS before the row). `SearchAsync` uses the same prefix-match-AND tokenizer as `HybridSearchService` so hyphenated queries don't get parsed as FTS5 NOT operators; exposed at `/api/v1/contacts/search?q=…` and over MCP as `find_contact`. `list_contacts` MCP tool does the plain listing. No UI wired yet — backend-only until the editor shape lands.

**Administration** (phases A1–A3; spec `docs/superpowers/specs/2026-09-26-admin-design.md`). Three roles: a user owns their personal workspace, a space owner their space, the **admin** (`users.is_admin`) the instance — approving accounts and system settings, **never reading content** (no admin route returns notes, files or secrets; `AdminUsersApiTests.AdminRoutes_NeverReturnContent` guards it). System schema **v11**: `users.state` (`UserStates`: pending/active/disabled/blocked, existing rows active), `quota_bytes` (stored at approval; enforcement arrives with the Files data lifecycle), `approved_by/_at`, `last_sign_in_at`; `messages` (the system inbox) and `admin_audit` (actor/action/target **ids only**). **Password resets are never silent** (admin spec's no-content rule can't stop an operator with disk access, so it is made visible): `POST …/users/{id}/reset-password` sends the temporary password straight to the user's linked chat DM when there is one (`deliveredTo`, the admin never sees it; `ChatText` `password.resetCode`), else returns it once to the admin; the user always gets a `password.reset` message (import too: `via: import`), and the change-password that uses it resolves that and sends `password.reset-used` — if it wasn't them, an admin went in. The Secrets page says plainly that only secret blocks are hidden from the operator. **Sessions end with the password:** `users.session_stamp` (system **v15**) rotates on every `SetPasswordAsync` (own change, admin reset, import); cookie sessions (`Cookies`/`Google`) carry it as `fishbowl_session` and `AccountStateMiddleware` ends one with an older stamp (401 / `/login`). `/api/auth/login` and `change-password` are rate-limited (10 a minute per address, 429 `too_many_attempts`; 1000 in `Testing`). **Every sign-in goes through `Fishbowl.Api.Accounts.AccountGate`** (Google's `OnTicketReceived` and `/api/auth/login` + change-password): blocked/disabled refuse (login page shows `?authError=`); with no active admin the signing-in active account becomes admin (Google-only installs, pre-v11 installs); a new identity is checked against `Auth:AllowedEmailDomains` (new accounts only) and `Auth:SignUp` — `approval` (default) creates a **pending shell** + one `user.pending` message per admin, `open` activates, `closed` refuses. `AccountStateMiddleware` (right after `UseAuthentication`) re-reads the state **per request**: pending reaches only `/pending` (server-rendered `pending.html`), `GET /api/v1/me` (carries `state`) and sign-out — everything else 403 `{error:"pending"}` / redirect; disabled/blocked drop the cookie and get 403 `{error:<state>}` (Bearer keys too) at the next request. Second wall: `DatabaseFactory` throws `InactiveAccountException` rather than create a personal DB for a registered non-active account; the scheduler iterates `ListActiveUserIdsAsync`. Admin API (`AdminApi.cs`, cookie + `IsAdmin`, Bearer 403): `GET /api/v1/admin/users` (metadata + `signUp` + `defaultQuotaBytes` from `Files:DefaultUserQuotaBytes`), `POST …/users/{id}/approve` (`{ quotaBytes?, makeAdmin? }`, 409 `not-pending`), `/reject` (deletes the shell, may ask again), `/block` (not yourself; `last-admin` 409), `/unblock` (unapproved → pending, approved → active); every admin write — incl. import, reset-password and config set/clear — is one `admin_audit` row. **Messages** (`MessagesApi.cs`, cookie-only): `GET /api/v1/messages` (`?unread=true`; for admins the server adds who a `user.pending` is about at read time — rows never copy names), `GET …/unread-count`, `POST …/{id}/read`; acting on a request resolves it (`done_at`) for every admin. System messages only — no chat. UI: the envelope `#fb-messages-btn` (badge = unread, refreshed on `fb:messages-changed`, navigation, every minute) opens the Messages window (`fb-messages-view.js`, inline Approve with a GB quota field / Reject / Block); Users (`fb-users-admin-view.js`) is a window app whose tile and palette entry exist only for admins, in the personal workspace; shared flows live in `js/lib/accounts.js` (`fb.accounts`). The kit has no mail icon — `kit-config.js` registers `mail`. Recovery: `tools/set-admin <userId|username>`. The Playwright fixture's injected user is an active admin. **A2 (manage):** `POST /api/v1/admin/users` (`{ username, displayName?, quotaBytes? }`) adds an **active** local user approved by the calling admin and returns its temporary password **once** (must change at first sign-in); `PATCH /api/v1/admin/users/{id}` is partial — `quotaBytes` (null = default, 0 = unlimited), `isAdmin` (grant only to active accounts; the last active admin can't be removed, 409 `last-admin`), `disabled` (not yourself; active ↔ disabled only — sign-in refused, the gate ends live sessions, **all the account's API keys are revoked**, data stays) — validated whole before anything is written, one audit row per changed field. In the UI each account row has a "…" `<sac-menu>` (Storage…, Reset password for local sign-ins, Make/Remove admin, Disable/Enable, Block/Unblock — rebuilt per render with only the items that fit the account's state) and the nav toolbar an "Add local user" action (a dialog); one-time passwords reveal like API tokens (re-shown until acknowledged). **System settings** are tabs of the System app below (`fb.systemSettings` in `js/lib/system-settings.js`): it renders `GET /api/v1/admin/config` (`ConfigSchema.Editable`) one tab per key-prefix group (Sign-in, Files & quotas, Export & archive, Apps, Integrations, Daily digest, Logging, HTTPS certificate, Other), with a choice list / GB / number / text input per key, per-row save with the server's validation message inline, secrets write-only ("Set" + Replace/Remove), and a restart notice for boot-bound keys; a new editable key appears without UI work (Digest and Logging keys are editable now too). **Chat fan-out:** `IMessageRepository` is `NotifyingMessageRepository` (Fishbowl.Api/Accounts) around `MessageRepository` — every new message also sends a **fixed subject line per kind** (`SystemMessageNotifier.SubjectFor`, never data, names or addresses) to the recipient's first enabled bot channel, in the background; a failed send is logged and never blocks the message. **A3 (lifecycle):** `DELETE /api/v1/admin/users/{id}?archive=` (archive **defaults to true**; not yourself, last-admin guard, 409 `owns-spaces` + the list while the account is the only owner of a space — `GET …/users/{id}/delete-check` tells the dialog first) ZIPs `users/<id>/` via `UserArchiver` (`IUserArchiveService`, the `SpaceArchiver` twin: personal.db and apps/*/app.db via online backup, files/ incl. trash, `manifest.json`) to `fishbowl-data/archive/users/<id>-<stamp>.zip`, verified before anything goes; then one transaction removes the users row, mappings, API keys (its own and its apps'), notification channels, link codes, memberships, messages to it and its per-user config latches, and writes a **tombstone** in `deleted_users` (system **v12**) — `AccountStateMiddleware` answers a session that outlived the delete with 403 `{error:"deleted"}` and `DatabaseFactory` won't recreate its personal DB; the folder goes last (parked as `users/.deleted-<id>` when locked). Same retention as space archives (`Archive:RetentionDays`, purged by `FilesMaintenanceService`); no restore UI — unzip into `users/<folder>/` and use the cold import. **System** (`fb.systemApp.open(tab?)` in `fb-system-view.js` — a **window app**, no route: the desktop tile `builtin:system` and the palette open a wide maximizable `<sac-window>`; admin-only, personal only; the last tab is remembered in localStorage) is one app with `<sac-tab-group>` tabs in one row: **Info** renders `GET /api/v1/admin/system`: version, data size by kind (personal workspaces, spaces, system.db, search model, logs), archive counts/sizes and retention, embedding model status, and when the scheduler last ran (`SchedulerStatus`, an in-memory singleton the reminder dispatcher and the daily maintenance stamp). The Users "…" menu has **Delete…** (archive checkbox checked; the owned-spaces list and only Close when blocked).

**Space roles, members and invitations** (space-apps spec phase 1, `docs/superpowers/specs/2026-09-28-space-apps-design.md`). `SpaceRole` is a staircase — **Reader < Member < Designer < Admin < Owner** (wire/DB `reader`/`member`/`designer`/`admin`/`owner`; system **v14** rebuilt `space_members` for the new CHECK and renamed `readonly` → `reader`) — and the checks compare: `CanWrite` (Member+), `CanDesign` (Designer+: schema, app code, triggers — used from phase 3 on), `CanInvite` (Admin+: invite, change roles, remove), `CanDeleteSpace` (Owner: delete/export), `CanGrant` (never Owner, never above your own). "Admin" in a space is always the space's; the instance admin is **Global Admin** in the UI (`users.is_admin` unchanged). `SpaceMembersApi.cs`, cookie-only: `GET /api/v1/spaces/<slug>/members` (any member; name + picture, never e-mail), `PATCH …/members/{userId}` `{ role }` / `DELETE …/members/{userId}` (Admin+, not the owner, not above your own role; yourself = leave, the owner can't), `GET|POST …/invites` + `DELETE …/invites/{id}` (Admin+; `{ role, days? }` 1–30, default 7 → `{ url }` **once** — only the token's SHA-256 is in `space_invites`; an invitation only works while its maker may still grant its role). **`GET /invite/<token>`**: signed in → joins (an existing member keeps a higher role) and lands in the space; signed out → the `fb_invite` cookie (`InviteCookie`, HttpOnly, ≤ 1 day) + `/login`, and `AccountGate` redeems it at sign-in (Google and local): **an invitation is an invitation** — a new identity skips the domain list and the sign-up policy (it is created pending and becomes active only when the redeem succeeds — else it is removed and the policy decides), a pending account becomes active (its `user.pending` resolved), every Global Admin gets a `user.invited` message; blocked/disabled still refuse; `/invite` is reachable for pending accounts. A spent/expired/unknown link → the login page's `authError`, or `/?invite=<code>#/` (a toast from `shell.js`) when signed in. UI: the users icon on each row of the Spaces window opens `fb.spaceMembers` (`js/lib/space-members.js`, a `<sac-window>`): members with role chips, a "…" menu per member (roles up to your own with a check on the current one, Remove; Leave on your own row), "Invite…" (role + validity → the link shown once with Copy) and the open invitations with Withdraw.

**Trash — one for everything** (space-apps spec phase 2). Deleting a note, todo, event or contact (`DeleteAsync` on the four repositories, optional `deletedBy` — space routes pass the caller, personal defaults to the owner) first writes the **whole row as a JSON snapshot** (`TrashSnapshots.TakeAsync`, blobs as `{"$b64":…}`) into the context DB's `trash` table (user/space schema **v13**) in the same transaction, then really deletes it — unique values are free again, event reminders go with the event. `ITrashRepository`/`TrashRepository`: restore re-inserts the snapshot's columns that still exist, **works or doesn't** (id taken again or a constraint fails → 409 `restore_conflict`, the item stays), rebuilds `contacts_fts` in the transaction and a note's FTS row + vector via `INoteRepository.ReindexAsync`. `TrashApi.cs`, cookie-only: `GET|DELETE /api/v1/trash`, `POST …/{id}/restore`, `DELETE …/{id}` + the space mirror `/api/v1/spaces/<slug>/trash` (members see, writers restore/delete); the list never carries the snapshot. `FilesMaintenanceService` purges it daily with the file trash's `Files:TrashRetentionDays` (0 = keep). Files keep their own `file_trash`; the **Trash app** (a window app, `fb-trash-view.js`, desktop tile `builtin:trash`, both workspaces) lists records and files together, newest first, with Restore (a file clash offers "as a copy"), Delete for good and "Empty trash" in the toolbar — no write buttons for a space reader.

**Space tables** (space-apps spec phase 3; `Fishbowl.Core.Tables`, `Fishbowl.Data.Tables.TableRepository` behind `ITableRepository`). **Spaces only** (`tables_space_only` otherwise). A table's definition is in `db_tables` / `db_columns` (user/space schema **v14**), its rows in `t_<name>` (the prefix keeps them apart from Fishbowl's own tables), a `multiple` link column's targets in `t_<table>__<column>`. Every row: `id`, required `title`, `author`, `created_at`, `last_modified`, `row_version`, `additional_data` (JSON ≤ 256 KB) — no soft delete. Column types say what is meant: `text`, `longtext`, `integer`, `decimal`, `yesno`, `date` (YYYY-MM-DD), `datetime` (stored UTC), `choice` (options, `multiple` = JSON array), `member` (a space member's id), `file` (a relative path), `link` (`link` = a space table or `notes`/`events`/`todos`/`contacts`; `multiple` = n:m) — per column description, required, default (not link/member/file), unique (unique index). **Links are foreign keys enforced in code**: a link must point at something that exists (`link_missing`), and **nothing that is linked to can be deleted** — `LinkGuard.EnsureUnlinkedAsync` runs in every row delete and, through `TrashSnapshots.TakeAsync`, in every note/event/todo/contact delete (409 `still_linked`); a table another table links to can't be dropped. Per table `ownRows`: a Member changes only rows they authored (`not_your_row`), Designer+ any. Role checks (`TableActor`): rows need `CanWrite`, schema `CanDesign`. Row updates are partial with optional `rowVersion` (`version_conflict`). Deleting a row (`"row"` + `$table`) or dropping a table (`"table"`: definition + all rows) goes to the **trash**; restore works or rolls back entirely (`RestoreRefused`). Dropping a column is final. Queries reuse the apps platform's `QueryDsl` (its `is_deleted` filter only applies when that column exists) plus `AggregateAsync` (count/sum/min/max/avg, one `groupBy`). Every refusal is a `TableException` (code, status, args; an `InvalidOperationException`, so MCP answers InvalidParams) and `TableErrorsMiddleware` (after `UseAuthorization`) turns it into `{ error, message, … }` anywhere in a request. REST `TablesApi.cs` under `/api/v1/spaces/<slug>/tables` (list/create/describe `?format=markdown`/alter/drop, `/{table}/rows` CRUD, `/query`, `/count`, `/aggregate`); scopes **`read:tables` / `write:tables` / `design:tables`** (on the keys page) on top of the key owner's role. **13 MCP tools** in `Fishbowl.Mcp/Tools/Tables/TableTools.cs` — `table_list`, `table_describe` (markdown), `table_create`, `table_alter`, `table_drop`, `row_insert`, `row_get`, `row_update`, `row_delete`, `row_query`, `row_count`, `row_aggregate`, `row_search`. **Searchable columns** (text/longtext/choice, `searchable: true`, switchable via `updateColumns`; user/space schema **v15**): a row of such a table is indexed as title + those values in `rows_fts` (FTS5) and `vec_rows` (sqlite-vec, the notes' model), keyed `<table>/<row id>`, in the same transaction as the write (vector best-effort while the model loads); delete/drop unindex, restore and any change to what is searchable re-index; `SearchAsync` blends them 70/30 like notes (`HybridSearchService.MergeScores`/`FtsQuery`, shared) — `GET …/tables/search?q=&table=` and `row_search`, **separate from note search** (its own scope; the palette only lists what it can open). **The Tables app** (`#/space/<slug>/tables/<table>`, `fb-tables-view.js`, desktop tile `builtin:tables` — `space: true`, so only in spaces): the space's tables on the left, the one in the URL in **`<sac-data-grid>`, vendored verbatim** from `SACRVM/sac-data-grid` at `js/vendor/sac-data-grid/` (the release ZIP's `sac-data-grid/` folder — `js/`, `LICENSE`, `VERSION`, currently 1.0.0; never edit, an upgrade replaces the folder; `sac-data-grid-source.js` is not loaded — `fb.tableGrid` is the source; it needs the kit's `sac-number-field`, `sac-select`, `sac-color-field`, `sac-segmented-control`, `sac-spinner`, `sac-tooltip`, loaded in `index.html`). `fb.tableGrid.build(def)` (`js/lib/table-grid.js`) maps column types to grid types (yesno → bool, datetime ⇄ local `yyyy-mm-ddTHH:MM`, choice → select / tags with index values, member and link → select with names/titles — link targets capped at 500, multi-links as tags of lower-cased ids) and wraps `fb.api.tables` as the grid's source: sort/filter → the query DSL, edits → row PATCH/POST/DELETE, server refusals marked on the cell they name. A Reader gets `mode="read"`; the user's column layout per table is kept in localStorage. Schema stays read-only in the UI. Guarded by `TablesTests`.

**A space's app code** (space-apps spec phase 4, `Fishbowl.Core.Files.AppsFolder`) lives as files in `files/.apps/<app>/`. Every member reads it; `FilesApi` refuses writing, deleting, moving or copying into or out of `.apps` (upload, folders, move, copy, delete, trash restore, transfer) below **Designer** (403 `apps_design_only`), a key additionally needs **`design:apps`**, `.apps` itself can't be renamed/moved/deleted (409 `apps_folder_fixed`), and the personal workspace has none (400 `apps_space_only`). The kit's `<sac-file-browser>` hides dot entries (kit 2.25); the Files toolbar's eye toggle sets `show-hidden` on both panes (`fb.filesStore.showHidden`, per browser). **Space apps** (`Fishbowl.Core.Desktop.SpaceApps`, `SpaceAppsApi.cs`): every `.apps/<folder>/app.json` with a custom-element `tag` (plus `name`, `version`, `icon`, `description`, `entry` — default `app.js`, a `.js`/`.mjs` in the folder) is an app of the space — the space's `GET …/desktop` lists it among `apps` as mode **`space`**, id `space.<folder>` (folder `[a-z0-9-]`), so tiles, burger, palette and the Apps window take it like an installed app (no update/permissions/remove: it isn't installed). It opens in the kit's sandboxed frame, **unpinned** (`integrity: false`) — a Designer's change runs on the next open. The frame document is DesktopApi's `/apps/frame/space/<slug>/space.<folder>` (cookie, members); the frame is opaque and sends no cookie, so the code comes from `GET /apps/code/<spaceId>/<folder>/<sig>/<file>`, `sig` = HMAC-SHA256 over `<spaceId>/<folder>` with `Apps:CodeKey` (system_config, made on first use) — no cookie, the signature is the key; it serves scripts, styles, JSON, images and fonts only (never HTML), `nosniff`, `CSP: sandbox`, CORS `*`, `no-cache`; the frame's CSP allows scripts from the entry's folder only. Whoever holds the URL reads that app's code — which every member may — and nothing else. A space app gets the space's data as **`context.space`** (the kit's `grant.api`, set by `fb.desktopApps`): `fb.api.spaceData(<slug>)` pinned to its space — `info`, `members`, `tables`, `describe`, `query`, `count`, `aggregate`, `search`, `get`, `insert`, `update`, `remove` (rows), and read-only `notes`, `note`, `todos`, `events(from, to)`, `contacts` — over the REST routes with the user's cookie, so the server's role checks hold; a refusal reaches the app as `{ code, message }` (the server's code, underscores as dashes). **The error store** (`AppErrors`, `IAppErrorRepository`, user/space schema **v17** `app_errors`, the newest 500; the same app + kind + message is stored once an hour): the server records an `app.json` it can't read (kind `manifest`, with why) whenever the desktop lists apps; the browser reports a space app that doesn't start (`load`), a refused `context.space` call (`call`) and the app's own `context.space.error(message, detail)` (`reported`) — `runtime` waits for the kit to forward a frame's uncaught errors (sacrvm-appkit#39). `GET|DELETE /api/v1/spaces/<slug>/apps/errors` (`?app=<folder>`) for Designers (a key needs `design:apps`), `POST` for any member's browser (cookie); MCP `app_errors`; the Apps window shows them to a Designer with Clear. **The space guide** (`SpaceGuide`, spec decision 23): markdown the server writes from the live space for an agent building its apps — the caller's role, how an app is laid out and runs (app.json, `mount(context)`, the sandbox, the kit's classes and components), writing code over the Files API, the `context.space` table, the space's tables (`TableJson.Markdown`), its apps (`SpaceAppCatalog`, also what the desktop and frame read) and, for a Designer, the latest errors; `GET /api/v1/spaces/<slug>/guide` (`read:tables`) and MCP `space_guide`. Not built yet: messages from apps.

**Space keys resolve to the space's id.** A space key's `context_id` is the slug; `ApiKeyAuthenticationHandler` looks the space up per request, refuses the key when its owner is no longer a member, and adds `fishbowl_space_id` and **only the scopes the owner's role allows today** (a Reader's key loses `write:*`, below Designer `design:*`) — `McpContextClaims.Resolve` opens `ContextRef.Space(<id>)`, the same `spaces/<id>/space.db` the web UI uses (before, REST and MCP calls through a space key used a `spaces/<slug>/` folder).

**Space delete and archived spaces** (Files phase 3, `SpaceArchiver` behind `ISpaceArchiveService`). `DELETE /api/v1/spaces/<slug>?archive=true|false` (owner, cookie-only; **archive defaults to true**, the dialog's checkbox too) first ZIPs `spaces/<id>/` — `space.db` and `apps/*/app.db` via online backup, `files/` incl. trash, plus `manifest.json` (slug, name, colour, members for the record, archived at/by) — to `fishbowl-data/archive/spaces/<spaceId>-<stamp>.zip`, re-opens it to check the entry count, and only then deletes the rows, the space's API keys (app keys too) and the folder (a locked one is parked as `spaces/.deleted-<id>`). **The archive folder is the truth** — no table; `/api/v1/archive/spaces` lists, downloads, restores and deletes, for the owner of record or the archiver. **Restore** = a new space id, the old slug if free else `<slug>-2`, the restoring user as the **only** member, no keys, and the files journal **epoch rotates**. `FilesMaintenanceService`'s daily tick purges archives older than `Archive:RetentionDays` (default 30, **0 = keep forever**) and sweeps `.deleted-`/`.restoring-` leftovers. **Per-user quota** (admin spec § Quotas) is enforced in `FileService` next to the per-workspace `Files:QuotaBytes`: `users.quota_bytes` (null → `Files:DefaultUserQuotaBytes`, 0 = unlimited) covers the whole `users/<id>/` folder plus every owned `spaces/<id>/` — a space bills its owner — on upload, copy and transfer (413 `field: "user_quota"`); crossing 90% sends one `quota.warning` system message (latch `Files:QuotaWarned:<userId>` in `system_config`, cleared when usage drops below). `GET …/files/usage` reports `ownerBytes`/`ownerQuotaBytes`. `tools/snapshot-data` copies `files/`, `apps/*/app.db` and `archive/` too.

**Files** (backend phase 1 + UI phase 2 + data lifecycle phase 3; spec `docs/superpowers/specs/2026-09-26-files-app-design.md`). Real files with real names in a real tree: `users/<id>/files/` and `spaces/<id>/files/` beside the context DB (created lazily on first write, so cold import moves them) — **the disk is the truth**. User/space schema **v9** adds only what the file system can't hold: `file_index` (rebuildable reconcile baseline + sniffed type / SHA-256 cache, valid while size+mtime match), `file_changes` (the journal; `seq` is the sync cursor), `file_trash` (bookkeeping for `files/.trash/<ulid>/<name>`) and a one-row `file_state` (epoch, compaction floor, case rule). **`IFileService` / `Fishbowl.Data.Files.FileService` is the single entry point**; only `DiskFileStore` touches `files/`, only `FilePathResolver` combines paths. Every mutation runs under a per-context lock: disk op, then one transaction (index + journal); a crash in between is repaired by reconcile (per folder on list, full tree before feed/snapshot throttled by `Files:ReconcileIntervalSeconds`, daily in `FilesMaintenanceService` which also sweeps stale `.~fb-*.part`, purges trash and compacts the journal). **Path safety:** wire paths are relative and `/`-separated; no leading slash, `..`, `\`, drive/UNC syntax, reserved `.trash` (root) or `.~fb-*`; links (symlinks, junctions, reparse points) are listed as `kind: link` and never followed; names follow **the host's rules** (`Fishbowl.Core.Files.FileNameRules`: Windows devices/forbidden chars/trailing dot/8.3 aliases, macOS `:`, UTF-8 byte length on Linux, plus a floor of no control/bidi chars) — a 400 `{ error: "invalid_name", rule, segment, message }`; case sensitivity is probed per volume (`FileVolume`). Uploads are a raw-body `PUT …/content` with `X-Fishbowl-Upload: 1` and **required** `If-None-Match: *` / `If-Match` (else 428, mismatch 412), streamed through a hidden temp file in the target folder + `IncrementalHash`, then renamed; an aborted upload leaves nothing. ETag = `<size>-<mtime ticks>`. Downloads stream with Range; every content response is `nosniff` and — unless `?inline=1` on a sniffed raster image/audio/video/plain text — `attachment` with a `sandbox` CSP; a sniffed `%PDF-` opens inline in its own tab under its own CSP (no sandbox). Type is sniffed from the first 4 KB (`FileSniffer`), never trusted from the client; HTML/SVG/XML/JS are never inline whatever their name. Limits are `system_config` keys with defaults (`Files:MaxFileBytes` 2 GiB, `Files:QuotaBytes` 20 GiB, `Files:InstanceCapBytes` 0, `Files:MinFreeBytes` 1 GiB → 507, `Files:TrashRetentionDays` 30, `Files:JournalRetentionDays` 90) read per request. Routes (`FilesApi.cs`, personal `/api/v1/files` + space mirror `/api/v1/spaces/<slug>/files`): `capabilities`, `list`, `stat`, `content` (GET/PUT), `folders`, `move`, `copy`, `DELETE ?path=` (trash; `&permanent=1` cookie-only), `trash` (+ `/{id}/restore`, `DELETE /trash/{id}`, `DELETE /trash` cookie-only), `usage`, `changes?cursor=` (410 `cursor_expired` on a foreign epoch / compacted / ahead cursor → take a `snapshot`, NDJSON), and cookie-only `POST /api/v1/files/transfer` (personal ↔ spaces). Scopes **`read:files` / `write:files`** (never added to existing keys); a space-bound key only reaches its own space's files. Logs carry a short path hash, never names.

**Files UI** (`#/files/*`, `fb-files-view.js`) is a two-pane commander built only from kit parts: two `<sac-file-browser multiple no-thumbnails>` side by side in a flat 50/50 grid (no splitter, no frames or corners — one hairline; header and footer share `--fv-bar-h`; the kit's `cursor-style="quiet"`, `flush` and `active="true|false"` (the view flips `active` on pane switch) give the quiet `--hover` selection and the `--accent` hairline under the active header; `--file-browser-bar-height` lines the bar up with the footer; the only `::part` styling left is mono rows and warm marks), a footer per column with `<sac-tab-group>` tabs then the status as plain text (left: *Browse*; right: *Browse* / *Preview* / *Properties* — Alt+P / Alt+I, both following the left pane's cursor; a phone shows only *Browse*), `<sac-shortcut-bar group="Files">` for the chords, `<sac-quick-look>` for the preview and the quick-look window (Space / Enter / double-click, a maximised `<sac-window>`, ←/→ walk the folder), `<sac-drop-zone overlay>` per pane for uploads, `<sac-progress>` beside the bar. **Keys are modern, no F-keys** (spec decision 13): Alt+N/R/C/M/P/I/U/S, Alt+1/Alt+2 (pane workspace menus), Delete (trash, no question) / Shift+Delete (asks, then permanent), mod+C/X/V (clipboard across panes and workspaces), mod+F (filter the folder), Tab (switch pane while a list has focus), `?` (sheet). The **left pane is the app's workspace and lives in the URL** — a kit prefix route: `#/files/<folder>` / `#/space/<slug>/files/<folder>`; walking folders never remounts the view (it listens for `sac:route` and repaints the toolbar, which `shell.js` clears on every hash change); picking another workspace for the left pane is a scope switch. The right pane's workspace + folder sit in `sessionStorage` (`fb.files.right`). The store is `fb.filesStore({ workspace })` (`js/lib/files-store.js`) — the kit's store contract over `fb.api.files.in("personal" | "space:<slug>")` (one level per request via `entries()`, stats cached; a `.folder` marker write = `POST /folders`); `fb.api.files` without `.in()` follows `sac.scope`. The view takes over delete and rename (`sac:request-remove` / `sac:request-rename` → `preventDefault`) so refusals become toasts. **Everything that crosses panes — Alt+C/Alt+M, drag and drop, paste, the phone's Copy to… / Move to… destination picker — is one `fb.api.files.transfer`** (`/files/transfer` works within a workspace too); a `name_exists` item asks **Replace / Keep both / Skip** (+ "for the rest too"), and uploads ask the same on a 412 (Keep both finds `name (n).ext`). Uploads go through XHR for progress (`fb.api.files.in(ws).upload`, `parents=1`, folder drops keep `relativePath`). No dead buttons: a read-only space pane gets `readonly` on its browser and no write item in the bar, the toolbar or as a copy/move target. The trash is a `<sac-window>` per workspace (Restore — as a copy on a clash —, delete permanently, empty). Kit 2.17 features in use: `delete-button="hover"` (the row's trash icon only on single-row hover, never while rows are marked), an Undo action on the Delete toast (`sac.toast` action, label `fb.files.undo` en/de; restores the just-trashed entries, as a copy on a clash — Shift+Delete has none), touch mark mode (long-press, `sac:selecting`/`sac:mark`; single-row actions leave the bar while several rows are marked, a finished action ends mark mode), `browser.focus()` for pane switches, and the Modified column follows `sac.regional` (set by `fb.format`). `FilesTests` in `Fishbowl.Ui.Tests` cover the keys, cross-workspace transfer with a clash, upload clashes, preview/quick look, the read-only pane, the phone (incl. long-press marking), hover-only delete + Undo, Tab focus, the date column, and that full Chromium really renders an inline PDF under `FilesApi`'s headers (the headless shell can't — that test launches `Channel = "chromium"`).

**Space-nested API shape.** Every resource the SPA shows in a workspace has a cookie-scoped personal path **and** a space-scoped nested path, and they share the handler logic (just a different `ContextRef`): notes, tags (CRUD + color + rename), todos (CRUD), contacts (CRUD, reject readonly writes), search/reindex, export/db (owner-only). Space routes live in `SpacesApi.cs`, go through `ResolveSpaceAsync` (validates membership + Bearer-context match), and reject a Reader's writes via `SpaceRoleExtensions.CanWrite()`. Bearer tokens bound to a space can only hit their own space's paths; a personal-scope token on a space URL is 403 even when the human behind it is a member — the token's context, not the user's membership, is the authoritative scope. The personal-only routes (`/api/v1/todos`, `/events`, `/contacts`, `/tags`) answer a space key with 403 (`PersonalKeysOnly()`); `/api/v1/notes` and `/search` resolve it to its space. Space create/list/get/colour are cookie-only.

**Dev ports.** In Development the host binds **both** `https://localhost:7180` **and** `http://localhost:7181`, and `UseHttpsRedirection` is skipped. The HTTP port is for programmatic clients (Claude Code's MCP over HTTP, `curl`) that don't want to deal with the self-signed dev cert; the HTTPS port stays the primary URL for browser + logged-in flows. A dev-only request-trace middleware logs `>> METHOD /path auth=… accept=…` and `<< … status scheme=…` on `/mcp` + `/api/*` so you can see what an MCP client is actually sending. Production: both the HTTP bind and the trace logger are skipped by `app.Environment.IsDevelopment()` gates.

**Prod ports.** Production binding is driven by what's in `system.db`. With ACME configured (`Acme:Domains`/`Acme:Email`/`Acme:AcceptTos` all set), `Program.cs` binds `0.0.0.0:80` + `0.0.0.0:443` and `UseHttpsRedirection` is active. Without ACME — fresh install or LAN-only deployment — Program.cs binds **`0.0.0.0:80` HTTP-only** so the operator can reach `/setup` on first boot, and `UseHttpsRedirection` is skipped (nothing's listening on 443 to redirect to). If `urls` is set in configuration — via `ASPNETCORE_URLS` env var or `--urls` CLI arg, both feed the same key — the fallback skips and Kestrel uses those URLs (operator escape hatch for a non-80 port; also how `PlaywrightFixture` pins its tests to a free loopback port without hitting the prod default). The "post-ACME" → "post-restart-binds-443" transition is why /api/setup returns `restartRequired: true` when ACME fields change.

**Dev tools under `tools/`.** `mint-dev-key` issues an API key directly against `ApiKeyRepository` without a browser session — supports `--scopes`, `--context user|space`, `--context-id <slug>`; token on stdout, metadata on stderr. `reindex-dev` calls `NoteRepository.ReEmbedAllAsync` against the disk (bypasses the cookie-only HTTP endpoint). `seed-dev-data` populates notes/todos/contacts in a context for quick UI + MCP iteration; sentinels (`seed:dev` tag on notes, `[seed-dev] ` prefix on contacts/todos) make it idempotent, `--force` overrides. `init-space <slug>` is the per-space bootstrap: creates (or reuses) a space with the given slug, mints a space-scoped API key with all read/write scopes by default, prints the bearer on stdout + a status banner on stderr. Stays agnostic about who consumes the bearer — downstream agent-CLI wiring (credential storage, MCP config) lives in the consumer's docs, not Fishbowl's. `snapshot-data` hot-backs-up the whole data dir via SQLite's online backup API to `fishbowl-backups/snapshot-<ts>/` — safe under live writes, intended for cron'd operator runs (see tools/snapshot-data/README.md). `set-config <key> [<value>]` writes a single `system_config` key (value from stdin when omitted, for secrets) — the post-setup side door for ACME/Discord/logging knobs and the digest opt-in (`Digest:Enabled`, `Digest:Hour`). `set-admin <userId|username>` makes an account an active admin — the lock-out recovery path. All read `system.db` via the real `DatabaseFactory`, share exit codes, and `tools/` is outside the product solution. `.mcp.json` at repo root (gitignored) holds Claude Code's local MCP config pointing at `http://localhost:7181/mcp`; regenerate the token with `mint-dev-key`.

**Per-space agent integration.** Any agent CLI that wants its own Fishbowl memory namespace gets its own **space** — file-boundary isolation, role-based membership, space-scoped MCP routes. `tools/init-space <slug>` bootstraps the space plus a space-scoped key. The bearer token's `fishbowl_context_type=space` claim carries the scope; there is no `project_id` MCP tool argument and no `X-Project` header — the token *is* the scope. The host also serves `/s/<slug>` as a 302 to `/#/space/<slug>/notes`, a thin URL-alias convenience for downstream link templates that prefer not to construct the SPA hash route directly.

**Desktop** (`#/`, `fb-hub-view.js` + `js/lib/desktop.js` → `fb.desktop`; spec `docs/superpowers/specs/2026-09-26-desktop-apps-design.md`, phase D1). One registry of built-in apps (Notes, Todos, Calendar, Files, Tables in a space, Messages, Trash, Apps; Spaces, API keys, Secrets personal; Users and System for admins, personal only) drives the tiles and the Ctrl/⌘K palette; only Notes, Todos and Calendar default to `medium`; every other tile (built-in or installed, in any workspace) defaults to `small` and follows them, so the small ones share medium cells four at a time. A tile stores a size only when it differs from its default (`fb.desktop.save`), so a colour or hide write never freezes it. **The desktop is built exactly like SACRVM Desktop** (`SACRVM/sacrvm-desktop`, the reference — same look, same behaviour): the kit's hub recipe (`.orb`, `.hub-container`, `<main class="grid">` of `<a class="tile">` with icon, `h2`, `p`), the kit's hover, **no Fishbowl styling over the kit tiles** — the view's only CSS is SACRVM Desktop's own (the `.tile-menu` "⋯" and the `size-wide`/`size-large` footprints, collapsed ≤768px). Each tile's `<sac-menu class="tile-menu">` is SACRVM Desktop's: Small / Medium / Wide / Large tile (✓ on the current one; small = icon only, consecutive small tiles share one medium cell four at a time in the kit's `.tile-pack`), a colour row (`<sac-swatch-grid>` of kit palette slots via `fb.accents`, "Default" = none; the colour is the tile's `--accent`), Hide. The arrangement is per workspace on the server (`fb.api.desktop`, key `builtin:<name>`): a menu pick writes that one tile; no reordering UI and no Edit mode (stored positions stay, unarranged tiles sort by registry index). Hidden tiles come back from the toolbar (`fb.toolbar`, "Show hidden tiles (N)" → a dialog with Show per tile), shown only when something is hidden. Only `canArrange` (personal, or the space owner) gets menus and that item. Tiles carry no badges or live previews. Don't restyle the desktop here: a change to how tiles look or behave belongs in the kit (and SACRVM Desktop), not in `fb-hub-view`. The palette is the kit's `<sac-command-palette>` (in `index.html`) filled via `sac.commands` by `fb.desktop.syncCommands()` — groups Apps, Create, Go, Workspace, Notes — Notes is a `sac.commands.registerSource` over the active workspace's hybrid search (`fb.api.search.query`, full text, as you type): title + the words around the first match, secret markers shown as a lock, picking one opens the note. View routes still register with `palette: false`: the kit palette scopes route hashes since 2.18, but Apps and Go already list them with the workspace's rules (hidden tiles, admin apps personal-only, Secrets never in a space), so a Views group would repeat them and offer pages that don't work there. Create/open hand-offs go through `fb.desktop.go(view, action, id)` → the view takes it with `fb.desktop.takeIntent(view)` on connect or on `fb:intent` (notes create/open, todos create, calendar create). The nav's search button (`#fb-search-btn`, outside `fb.toolbar`) opens the palette — on a phone and inside the notes editor, whose Ctrl+K is its own link shortcut. **Installed apps** (`js/lib/desktop-apps.js` → `fb.desktopApps`, kit `lib/apps.js` + `identity.js` in `index.html`) are tiles like the built-ins (key `app:<id>`, SACRVM Desktop's `.tile-meta` origin line: host · version · mode) with three more menu items, each only when it applies: "Update to v…" (found by re-reading every sandboxed app's manifest once per session when the desktop opens — never a message), "Permissions…" (sandboxed), "Remove from this desktop" (keep data / delete data → trash). There is no install tile on the desktop: installing is the Apps window's "Install an app" (only for `canInstall` — policy + space owner). Install = URL → `sac.apps.inspect` (this browser reads app.json and hashes the entry; the server never fetches) → the review dialog (origin, version, code pin, mode — trusted only personal and when `canTrust`; grants: files = its own folder, identity starts at "Nothing" whatever the manifest asks, the `connect` servers shown read-only) → `fb.api.desktop.install`. Apps run through the kit: every installed app opens as a kit **window** (the host's choice — a view app would take over the hash); sandboxed = `sac.apps.add(…, { isolated: true, grant, integrity })` with `sac.apps.frameUrl` pointing at `/apps/frame/…`; trusted = same-realm, unpinned. The **files grant is the app's storage**: `desktop-apps.js` sets `sac.fs.backend` so `context.fs` of an installed app lives in the workspace's Files at `Apps/<name>` (JSON entries in one `.fishbowl-app.json`, bytes as real files); without the grant its writes are refused and it runs without storage. The same grant gives the app its own picker (kit 2.20, `grant.files = { provider }` → `context.granted.files === "scoped"`): `sac.files.virtual` over the workspace's Files store, jailed in `Apps/<name>` — it never sees the rest of Files (`kit/js/lib/files.js` is loaded for this). **Apps** (a window app, `fb-apps-settings-view.js`, desktop tile `builtin:apps`; its policy line names `Apps:Install` plainly — `installPolicy` comes with `GET …/desktop`) lists the workspace's apps (host, version, mode chip, grants) with Update / Permissions / Remove and "Install an app" in the toolbar — write buttons only for whoever may; a card says what the policy allows. `AppsTests` installs a real app from a second loopback origin (`FixtureAppServer`).

**Desktop apps — server side** (`Fishbowl.Core.Desktop`, `DesktopRepository`, `DesktopApi`; spec `docs/superpowers/specs/2026-09-26-desktop-apps-design.md`). User/space schema **v10**: `desktop_tiles` (a workspace's tile arrangement: position REAL, size, palette colour, hidden) and `desktop_apps` (installed apps: the manifest the owner's browser read, origin, entry URL, SRI pin, mode, granted capabilities). `/api/v1/desktop` + `/api/v1/spaces/<slug>/desktop`: **cookie-only** (Bearer 403 — installing code is never an agent's act), members read, **only the workspace owner writes** (sharing a space shares its apps). **The server never fetches a foreign URL**: `AppManifestValidator` checks what was posted (https origin, loopback http for dev; entry on the manifest's own origin; `permissions` ⊆ files/identity — the kit's object form `{ "files": true }` or a list — `connect` = exact https origins, `opens` = MIME/ext). Two modes: `sandboxed` (default, needs the entry's SRI hash — new code re-pins via PATCH) and `trusted` (same-realm, no pin, **personal only**). Admin policy keys `Apps:Install` (everyone|admins|off, default everyone; a space owner installs unless `off`) / `Apps:Trusted` (default **admins**), `Apps:AllowedOrigins`, `Apps:StoreOwners`, `Apps:StoreTopic`. An app's data lives in Files at `AppDataFolders.For(name, id)` (`Apps/<name>`); `DELETE …/apps/{id}` keeps it unless `?purgeData=true`. Grants: `files`, and identity as `identity` (name + picture) or `identity:pseudonymous` (a per-app id), never both. `GET /apps/frame/{user|space}/{id|slug}/{appId}` serves a sandboxed app's frame document in the **kit's harness shape** (`<html data-sac-guest>`, `/kit/css/ui.css`, `/kit/js/all.js`, the kit's `/kit/js/lib/app-guest.js` — never the entry: the bridge hands the pinned entry over at boot) under `FrameCsp.Build` (the kit's harness CSP as a header: kit paths on Fishbowl's own origin, the entry's folder, `connect-src` = declared origins + blob:/data:, `frame-ancestors` Fishbowl); `/kit/fonts/*` answer with `Access-Control-Allow-Origin: *` for the opaque-origin frame. Anything it can't serve is 404. Origins pass `AppOrigins.IsSafe` before they reach a header.

## Conventions

- **Dapper snake_case via `DapperConventions.Install()`** in `DatabaseFactory` static ctor — `created_at` → `CreatedAt` works automatically. `JsonTagsHandler` handles `List<string>` ↔ JSON for `notes.tags`. Use `QueryAsync<T>`, never `QueryAsync<dynamic>` with manual mappers.
- **FTS5 + vec_notes must stay synced.** `notes_fts.rowid` maps to `notes.rowid` via `(SELECT rowid FROM notes WHERE id = @Id)`. On delete, remove from `vec_notes` AND `notes_fts` BEFORE `notes`. Tags are space-joined string (not JSON).
- **Logging via `ILogger<T>?` defaulting to `NullLogger<T>.Instance`** so tests can construct objects directly. **Never log PII** (email, name, content, secrets, tokens). Sinks: console always, plus rolling daily file at `fishbowl-data/logs/host-{yyyy-MM-dd}.log` (Serilog) — file sink suppressed in `Testing` env so smoke fixtures don't accumulate temp artefacts. Retention + plain/JSON format read from `system.db` (`Logging:RetentionDays`, `Logging:Format`) via `BootConfig.LoadLogging` at boot; defaults are 7 days + plain text. Changing either needs a host restart (acceptable — ops don't retune logging hot).
- SQLite `DateTime` stored ISO-8601 (`.ToString("o")`); booleans as `INTEGER 0/1`; IDs are ULIDs.
- Secrets use `:::secret` markdown block + separate `content_secret BLOB` (client-encrypted). **Never include secret content in FTS, embeddings, or chat responses** — non-negotiable; enforced by `SecretStripper` on every MCP return path (it also strips labelled blocks, `:::secret <label>`). **One block grammar** in the editor (vendored `sac-md-secret.js`), the client encryption (`api.js` `replaceSecretBlocks`, exposed as `fb.api.secretBodies` for tests) and `SecretStripper`: a block opens on a `:::secret`/`::secret` line (generous: any case, indented, optional label) and closes on a line that is `:::end`/`::end` optionally followed by whitespace and text (strict: never `::endpoint=`, never indented); an unclosed block runs to the end of the note — everything the editor masks is encrypted and stripped, never less. Agents can't rewrite the text of a note with secrets (`update_memory` refuses, a key's PUT is 409 `secret_note`); title and tags they may change.
- **Secret vault v2** (`js/lib/vault.js`, spec `docs/superpowers/specs/2026-09-25-secret-vault-design.md`): one random vault key per user encrypts every block (AES-GCM, AAD `<note id>|<index>`); the server stores only wrapped copies of it in `vault_keyslots` (user DB **v7**) — a passphrase slot (PBKDF2-SHA256 600k, salt in the slot) and a recovery slot (24 BIP-39 words → HKDF; list vendored at `js/vendor/bip39/english.txt`, **hash-pinned in vault.js** — never edit it). Unlocked key is non-extractable and memory-only; auto-lock after 15 min. `/api/v1/vault` is cookie-only + personal-only (Bearer 403). `content_secret` must be a `{ "v": 2, blocks }` envelope (`SecretEnvelope`), and **spaces hold no secrets**: `NoteRepository` refuses any secret in a space context on every write path (400 via `ResourceValidationKind.Invalid`; `ValidationResults.From` maps Invalid → 400, SizeLimit → 413). Passkeys are a third slot kind: WebAuthn PRF output → HKDF (`prf-hkdf-sha256` kdf, salt per slot), probed at runtime (`fb.vault.passkeySupported()`), offered at setup and first in the unlock dialog; a vault always keeps a passphrase or recovery slot (server 409 `last-recoverable-slot`). **Secrets** (a window app, `fb-secrets-settings-view.js`, desktop tile `builtin:secrets`, personal only) lists the slots and runs add passkey / change passphrase / new recovery key (+ printable emergency kit) / rename / remove through `fb.vault` — each asks for a way in again, because the session key is non-extractable. Auto-lock minutes are a user setting (`users.vault_auto_lock_minutes`, system **v10**, `VaultSettings.AutoLockChoices`, via `PATCH /api/v1/me`). WebAuthn needs a domain, not an IP: the passkey UI test uses `localhost`.
- **UI language (EN/DE)** is the kit's: `sac.lang` / `sac.t` / `sac.i18n.add`, no Fishbowl i18n layer. English stays inline as the fallback — `fb.t(key, fallback, vars)` (`js/lib/i18n.js`: `sac.t` plus `{name}` placeholders) or `data-t` / `data-t-title` / `data-t-aria` / `data-t-placeholder` on static markup (`fb.i18n.apply`); German lives in one table, `js/i18n/de.js` (keys `fb.<area>.*`, "du", values HTML-safe), the kit's components use `kit/js/i18n/de.js`. The language is a per-user setting independent of the date format: `users.language` (system **v13**, `Languages.Codes`, null = automatic — the browser's language when there is a table, else English), `PATCH /api/v1/me` (partial), chosen in the profile window above the date format; the shell calls `sac.lang.set(me.language ?? "auto")` (which mirrors it into localStorage for pages that load before `/me`). A switch re-registers the route labels under `fb.route.<path>` (burger, phone title — views keep registering English), repaints the shell and the palette and remounts the view, like a date-format change. Translated so far (phase 1): shell, profile, desktop and app dialogs, palette, Messages and the request actions; (phase 2) Notes with the tag manager, Todos, Calendar and Files — their German in `js/i18n/de-apps.js` (one extra table per area; counts are two keys, `<key>-1` and `<key>` with `{n}`), and `fb.format`'s month/weekday names follow `sac.lang`; (phase 3) the settings and admin pages, the vault dialogs and the emergency kit in `js/i18n/de-settings.js`; server error codes become text on the client through `fb.errors.text(err, fallback)` (`js/lib/errors.js`: code → `fb.errors.<code>` filled from the body's arguments; every refusal a person can see goes out through `Fishbowl.Api.ApiErrors` as `{ error: <code>, message: <English>, …args }` — config validators return a `ConfigError` — so the English `message` stays for agents and the client translates the code; a code without a translation for the page language shows `message`; guarded by `I18nTests.ErrorCodesCountsAndSettings_HaveGermanEntries`, which scans the server for codes); `/login`, `/setup` and `/pending` choose de/en in a small inline script (localStorage `sac-lang`, else the browser language — no Accept-Language on the server); the chat subject lines follow the recipient's `users.language` (`SystemMessageNotifier.SubjectFor(kind, language)`, null → English); `I18nKeyTableTests` checks every key those files use has a German entry. The Playwright browser runs `--lang=en-US`, so UI tests assert English unless they switch.
- **Dates go through `fb.format`** (`js/lib/format.js`), never `toLocale*(undefined)` or native date/time inputs: browsers only expose the UI *language*, never the OS regional format (by design, anti-fingerprinting), so English Chrome would show US dates. The format is a user setting (profile → Date & time format; `users.date_format` ∈ `DateFormats.Names` iso/de/uk/us, null = ISO; `PATCH /api/v1/me` is partial). Date inputs are the kit's `<sac-date-field>` + `<sac-time-field>`, driven page-wide by `sac.regional` (`fb.format.set` maps iso/de/uk/us → `iso`/`dmy.`/`dmy/`/`mdy/` + h23/h12); `fb.format.attachInput(input, { time })` swaps a placeholder `<input>` for the pair, both `size="regular"` (the date field keeps the id and fires `change` for both), `readInput` → Date|null (empty time = 09:00), `writeInput`, `setInputTime` (all-day). A format change remounts the current view.
- **Todo order is the user's**: `todos.position` (user DB **v8**, REAL). Create appends (`MAX+1`), a PUT without `position` keeps it, a drag in the todo list (`sac.sortable`) writes one row — the midpoint of its new neighbours. The list sorts open before done, then by position; due dates don't reorder.
- **System tags** carry three flags (`is_system`, `user_assignable`, `user_removable`) — set in `Fishbowl.Core.Util.SystemTags.Seeds`. Current seeds: `review:pending` (removable by user), `source:mcp` (locked). Rename/delete of `is_system=1` rows rejected in `TagRepository`.
- Modding rule: "disk file wins, else default" — components/styles/scripts/templates only. `fishbowl-mods/` is currently the dev overlay (junctions into `Fishbowl.Data/Resources`); see `docs/slimming-plan.md` for its pending fate.

## CI

`ci.yml` runs on push to master and PRs (Linux + Windows): `dotnet format --verify-no-changes`, `dotnet build`, `dotnet test`. `release.yml` on `v*` tag publishes per-RID `Fishbowl-{version}-{rid}.zip` artefacts (each containing an `app/` directory with the self-contained single-file binary) for `win-x64`, `linux-x64`, `osx-x64`, `osx-arm64`.

## Husky launcher

The host attaches to [Husky](https://github.com/SACRVM/husky) when the launcher hosts it (`HuskyClient.AttachIfHostedAsync` returns `null` under `dotnet run` / debugger, so dev is unaffected). Husky-driven shutdown forwards to `app.StopAsync(ct)` so hosted services (Discord bot, embedding initializer, ACME renewal) drain cleanly before the binary swap. End users run `Husky --repo SACRVM/the-fishbowl --asset 'Fishbowl-{version}-<rid>.zip'`; Husky reads `husky.config.json` from the repo root for `name` + `executable` + timing knobs (currently Windows-pathed; Linux/Mac users override `executable` in their local config). Husky preserves anything outside the update package, so `app/fishbowl-data/` survives upgrades.

## Firepit artifacts

When you produce a file the user will want to open — a report, screenshot, diagram, generated image, log excerpt, build output, or an executable you built for them to run — pin it with the `firepit_artifact_add` MCP tool so it appears in the project's paperclip pane. Do this as you produce it, not at the end of the session; a path buried in scrollback is a path the user has to hunt for. Pinning only links the file — it stays where it is, and `firepit_artifact_remove` never deletes it. Check `firepit_artifact_list` first so you update an existing entry instead of piling up near-duplicates, and unpin what has gone stale.
