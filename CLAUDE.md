# CLAUDE.md

Guidance for Claude Code in this repository.

## What this project is

Self-hosted personal memory + assistant. **`CONCEPT.md` is the target spec**, but the project is being deliberately slimmed against it — external sync, scripting and the sideloaded-plugin ecosystem have been dropped rather than deferred. Projects: `Fishbowl.Core`, `.Data`, `.Api`, `.Host`, `.Mcp` (8 tools), `.Search` (hybrid via `Fishbowl.Data.Search`), `.Bot.Discord` (real bot), `.Scheduler` (event reminders + daily digest). Every project in the solution has code in it. Don't reintroduce a subsystem just because CONCEPT.md still names it — check `docs/slimming-plan.md` first. See `CONTRIBUTING.md` and `docs/superpowers/` for active work.

## Working style — adaptive programming

Find the closest existing solution and **extend it**, don't parallel it. Almost-fits → add overload/option/partial. Genuinely wrong → say so and migrate callers. **Never silently diverge.**

- **HTTP endpoints**: `MapXxxApi()` extensions on `IEndpointRouteBuilder`; resolve the request's scope via `McpContextClaims.Resolve(user)` → `ContextRef` (User or Space), call a repository. Gate with `.RequireScope("read:notes")` etc. — cookie principals bypass scope; Bearer principals must match. Routes under `/api/v1/`.
- **Repositories**: interface in `Fishbowl.Core.Repositories`, impl in `Fishbowl.Data.Repositories`, `AddScoped`. Access via `DatabaseFactory.CreateContextConnection(ctx)` or `CreateSystemConnection()`. The legacy `CreateConnection(userId)` is a `ContextRef.User`-alias kept for cookie callers.
- **Multi-step writes**: `_dbFactory.WithContextTransactionAsync(ctx, async (db, tx, ct) => …)` — see `NoteRepository` for `notes` + `notes_fts` syncing.
- **Schema changes**: add `ApplyVN` in `DatabaseFactory`, bump `PRAGMA user_version`. No EF Core, no migration runner.
- **UI resources/scripts/templates**: `IResourceProvider.GetAsync(path)` only (disk → DB → embedded). Never direct file I/O.
- **Bot clients**: implement `IBotClient` (`Fishbowl.Core.Plugins`) and `AddSingleton<IBotClient, …>` in `Program.cs`. In-tree only — there is no plugin loader and no sideloading. Both scheduler dispatchers fan out over `GetServices<IBotClient>()`.
- **Configuration**: in `system.db` via `ISystemRepository.Get/SetConfigAsync` — never `appsettings.json`, never env vars for runtime config.
- **Frontend backend calls**: `fb.api.notes.list()` etc. — 401s auto-redirect to `/login`. Never `fetch` directly from views/components.

## Architecture

**Dependency direction:** `Host → Api/Bot.Discord/Sync/Scheduler/Scripting → Data/Search → Core`. `Fishbowl.Host` is the **only publish target**; everything else is a library. No cycles, no upward refs.

**One `DatabaseFactory` (singleton), three DB locations:**
- `CreateSystemConnection()` → `fishbowl-data/system.db` — `users`, `user_mappings`, `spaces`, `space_members`, `api_keys`, `system_config`.
- `CreateContextConnection(ContextRef.User(userId))` → `fishbowl-data/users/{userId}/personal.db` — notes, events, todos, tags, notes_fts, vec_notes. Folder-per-context: dropping the whole `users/{userId}/` folder onto another instance moves the user's data atomically (cold import).
- `CreateContextConnection(ContextRef.Space(slug))` → `fishbowl-data/spaces/{spaceId}/space.db` — identical schema to user DBs. Folder is keyed by the space's ULID, not its slug — slug can change (rename) while the folder stays put. `ResolveSpaceAsync` translates slug→id before opening.
- Legacy flat user layout (`users/{id}.db`) auto-migrates to `users/{id}/personal.db` on first open via `MigrateLegacyLayoutIfPresent`. The old `Team` primitive's on-disk layout (`teams/{id}/team.db` and ancient flat `teams/{id}.db`) is renamed wholesale to `spaces/{id}/space.db` by `MigrateTeamsFolderToSpaces`, which runs once at `DatabaseFactory` construction. Both are idempotent and never overwrite a pre-existing new-path file. The `Team`→`Space` table/api_keys rename is system-schema **v8** (`ApplySystemV8`).

Lazy migrations keyed on `PRAGMA user_version` — heads today: user/space DB **v10** (desktop), system DB **v11** (administration). Dapper raw SQL; IDs are ULIDs (`Ulid.NewUlid().ToString()`).

**sqlite-vec loaded on every context open.** `SqliteVecLoader.LoadInto(conn)` enables extension loading, calls `LoadExtension("vec0")`, then flips extensions back off. Binaries ship via the `sqlite-vec` NuGet package (v0.1.7-alpha.2 by roji + jeffhandley) — MSBuild drops them under `runtimes/{rid}/native/` automatically. System DB skips this (no vec tables there).

**Two auth schemes, one principal shape.** Cookie (Google OAuth; default) and ApiKey (Bearer `fb_live_…`). On first login, `Program.cs` creates a Fishbowl user, maps `(provider, providerId) → internalUserId`, adds a `fishbowl_user_id` claim. Bearer keys additionally carry `fishbowl_context_type` + `fishbowl_context_id` + one `scope` claim each — `McpContextClaims.Resolve(user)` collapses all of that to a single `ContextRef`. The cookie scheme forwards Bearer requests to ApiKey via `ForwardDefaultSelector`, so `.RequireAuthorization()` is scheme-agnostic. Data isolation is by file boundary, not row filtering.

**OAuth creds in `system.db`, not `appsettings.json`.** `GoogleOptions` binds against `ConfigurationCache` populated at startup by `ConfigurationInitializer : IHostedService`. `POST /api/setup` writes both DB and cache so changes propagate without a restart. Unconfigured options use sentinel `"placeholder"`.

**API/MCP paths return 401, not 302.** `OnRedirectToLogin` is overridden so `/api` and `/mcp` requests get `401` instead of redirect to Google — browsers following the redirect would ruin Bearer/MCP flows. OpenAPI doc at `/api/openapi.json`.

**`/setup` locked after config.** Once `Google:ClientId` is set, `GET /setup` and `POST /api/setup` return `404` (not 302 — harder to bypass). Validates: ClientId ends `.apps.googleusercontent.com`, ClientSecret ≥ 20 chars. No antiforgery (only responds when unconfigured).

**`IResourceProvider` serves the web UI and mods.** Three-tier: disk (`fishbowl-mods/{path}`) → DB (not yet wired) → embedded in `Fishbowl.Data.dll`. **Only embedded hits are memory-cached; disk hits are re-read per request** — "disk file wins" includes edits, so the dev overlay shows changes on F5 without a restart (pinned by `ResourceProviderTests`). `MapFallback` handles non-API paths; unmatched `/api/*` short-circuits to 404 (so it doesn't serve `index.html`). The private `TryOpenEmbeddedStream` helper tries three path forms because MSBuild's `RecursiveDir` produces Windows-style paths on Windows — keep it.

**Discord bot** (`Fishbowl.Bot.Discord`) is the reference `IBotClient` impl, in-tree, not a sideloaded plugin. `DiscordBotHostedService` owns the `DiscordSocketClient` for the host's lifetime — Bulk-overwrites global slash commands on `Ready`, dispatches `SlashCommandExecuted` to `SlashCommandRouter` via a fresh DI scope per invocation, and defers immediately so the 3-second interaction deadline doesn't bite slow paths (`/search` hits the embedding model). DM-only invariant: guild invocations rejected hard at the dispatcher regardless of declared contexts. **Seven commands** in `Commands/*Handler.cs`: `/help`, `/link <code>`, `/unlink`, `/remember`, `/search`, `/recent`, `/upcoming [days]` (calendar events for the next N days, default 7 — times as Discord `<t:…>` markup so they render viewer-local; recurring occurrences pre-expanded by `GetRangeAsync`). `/link` redeems one-shot codes from `IDiscordLinkRepository` (10-min TTL, atomic burn) and writes both `user_mappings (provider="discord", provider_id=<discord_user>)` and `notification_channels` so the DM channel is cached for future sends. `/unlink` is the inverse — deletes the mapping then removes the channel. Token bound from `system.db`'s `Discord:BotToken` via `ConfigurationCache` (same path as Google); empty/`"placeholder"` token → service no-ops with a warning so the host still boots on fresh installs. `/api/setup` accepts and validates `DiscordBotToken` (length + dot-separator shape) and flags `restartRequired: true` because the gateway connection binds at startup. `DiscordBotClient.SendAsync` resolves `notification_channels` → DM channel id → posts; `ReceiveAsync` is deliberately an empty stream (slash-commands not message events). Cold-DM fallback: when the cached channel id misses the gateway cache, looks up the mapped Discord user via `ISystemRepository.GetProviderIdForUserAsync(userId, "discord")`, fetches the user (gateway → REST), opens a fresh DM with `CreateDMChannelAsync`, and re-caches the new channel id so the next send hits the fast path. `SendAsync` is wired live: `Fishbowl.Scheduler.ReminderDispatcher` fires it on event-reminder triggers (see Scheduler section below). Search/recent return titles only — content never leaves the bot (even non-secret notes might be long, or the user might be on screenshare).

**Apps platform** (`Fishbowl.Core.Apps`, `Fishbowl.Mcp.Tools.Apps`, `AppsApi`). CONCEPT.md § Apps — mini-apps with their own SQLite, their own owner-declared schema, their own scope-gated MCP/REST surface. Each App nests under its owner (`users/<id>/apps/<appId>/app.db` or `spaces/<id>/apps/<appId>/app.db`); the apps registry table lives in the owner's user/space DB (user-schema v6), so dropping a space folder onto another instance moves the space **with** its apps atomically. `system.db` schema v7 widens `api_keys` to a third context type with paired `owner_type`/`owner_id` columns — the Bearer token *is* the App scope; there's no `app_id` argument on MCP calls. `McpContextClaims.ResolveApp(principal)` collapses the three claims into an `AppRef(ownerType, ownerId, appId)`. Owner-defined tables get **eight server-injected base columns** (`id` ULID, `title` NOT NULL, `author`, `created_at`, `last_modified`, `row_version`, `is_deleted`, `deleted_at`, `additional_data`) plus a mandatory `idx_<table>_is_deleted`. `additional_data` is a JSON ride-along, capped at 256 KB (ResourceValidationException → InvalidParams); the query DSL rejects filters on it explicitly. The DSL is MongoDB-style JSON (`$eq $ne $lt $lte $gt $gte $in $like $isNull $isNotNull` + `$and $or $not`), validated against the live schema and compiled to parameterised SQL via `QueryDsl.Compile`. Safety caps: depth ≤ 5, leaves ≤ 100, `$in` ≤ 50, `limit` ≤ 500 — caps return `QueryDslException` → InvalidParams. **Scopes** `app:read` / `app:write` / `app:admin` gate row reads, row writes, and DDL respectively (single-app-wide; no per-table or per-row scopes in MVP). **13 MCP tools** in `src/Fishbowl.Mcp/Tools/Apps/` (`app_list_tables`, `app_describe_table`, `app_create_table`, `app_alter_table`, `app_drop_table`, `app_create_index`, `app_insert`, `app_get`, `app_update`, `app_delete`, `app_restore`, `app_query`, `app_count`) join the existing `ToolRegistry`. REST mirror at `/api/v1/apps` — cookie-only lifecycle (`POST /`, `GET /`, `GET|PATCH|DELETE /{ownerType}/{ownerId}/{slug}`) + cookie-only key mgmt under `.../keys` + Bearer-or-cookie data plane under `.../tables`, `.../rows/{table}`, `.../query/{table}`, `.../count/{table}`. `{ownerType}` ∈ {user,space}; user owners use the user-id, space owners use the space-slug (resolved to ULID by `ResolveAppAsync` before any repository call — consistent with the space-folder rename invariant). DELETE uses `?confirm=<slug>` (minimal-API doesn't infer DELETE bodies) and drops the whole `app.db` folder. `tools/init-app <slug> --owner space:<slug>|user:<id>` bootstraps an app + mints an app-scoped key in one step; the bearer goes to stdout, status banner to stderr (same shape as `init-space`). App data **never** appears in `search_memory` / `list_pending` / hybrid search — they read from the owner DB, not app DBs. App keys never authorise `read:notes` / `write:notes` etc., so an app's agent stays sandboxed. Out-of-MVP follow-ups: per-table FTS5/vector index, triggers, cross-app reads, form-builder UI, slug rename, owner-cascade delete (currently a space with apps still deletes via `SpaceRepository.DeleteAsync`; the leftover `apps/` subfolder is operator-cleanup). Spec: `docs/superpowers/specs/2026-05-13-apps-platform-design.md`.

**Scheduler** (`Fishbowl.Scheduler`) runs as `IHostedService` and dispatches event reminders. Ticks every minute with a 30s startup delay; on each tick enumerates personal-context users via `ISystemRepository.ListUserIdsAsync`, opens each user's context DB, runs `IEventRepository.ListDueRemindersAsync(ctx, from, to, notAncient)` which selects events whose `start_at − reminder_minutes` falls in the half-open window. Catch-up window is 6h on first boot so a restart doesn't drop notifications that became due during downtime. The `notAncient` guard (start_at within past 24h) prevents a Monday-morning dispatcher from drowning in long-past triggers. For each due event the dispatcher checks `INotificationChannelRepository.GetAsync(userId, bot.Name)` against each registered `IBotClient` in order; first bot with an enabled channel wins. After a successful `SendAsync` it inserts a `reminders` row with `sent_at` set — that row is the dedupe latch for subsequent ticks (`IReminderRepository.GetSentTriggersAsync`, keyed on `(event_id, scheduled_at)` so each occurrence of a recurring event fires exactly once). **No record when delivery isn't attempted** (channel missing/disabled): the user might link Discord later, and we want the original reminder to still fire. **RRULE expansion is implemented** via the shared subset parser `Fishbowl.Core.Util.RRule` (FREQ=DAILY/WEEKLY/MONTHLY/YEARLY + INTERVAL + BYDAY-weekly + COUNT/UNTIL): `ListDueRemindersAsync` returns recurring events as per-occurrence `IsRecurringInstance` clones with `StartAt` set to the occurrence (UTC-normalized via `TimeUtil.AsUtc`); out-of-subset rules degrade to a single DTSTART occurrence. **Daily digest** (`DailyDigestDispatcher`, same file layout) sends one "here's your day" DM per user per day — today's events + due/overdue todos; opt-in via system config `Digest:Enabled=true` + `Digest:Hour` (server-local, default 7), set with `tools/set-config`; per-user latch is the config key `Digest:LastSent:<userId>`, empty days stay silent but latch, no-channel days don't latch (link-later still delivers same-day). Space-event reminders remain out of scope for MVP — recipient semantics for shared events need a design call. Multi-platform fan-out is the natural next step when the model needs to grow.

**UI is vanilla JS SPA — no framework, no build step, built on the vendored SACRVM APPKIT.** The kit lives verbatim at `Resources/kit/` (release ZIP's `kit/`, `kit/VERSION` says which — currently 2.15.0); **never edit it**, re-vendor instead (appkit `CONSUMING.md`). `index.html` is the shell: one global `<sac-nav id="fb-nav">` + `#app-root`, `kit/css/ui.css` loaded after `css/app.css` (kit wins; `app.css` keeps Fishbowl-only rules: tag palette, vault, auth pages). **Routing, scope, icons and dialogs are the kit's, with no Fishbowl layer over them**: views register with `sac.router.register("#/path", "tag-name", { label, icon })`, navigation is `sac.router.navigate`, confirms are `sac.dialog`, icons `sac.icons`. `js/lib/kit-config.js` (right after the kit's lib scripts) only sets `sac.scope.configure({ prefix: "space" })` and registers the `fish` brand icon. `window.fb` holds just what is Fishbowl's own: `fb.api`, `fb.tags`, `fb.vault`, `fb.tagManager`, `fb.toolbar`. `js/lib/shell.js` (loaded last) renders `fb.toolbar.set([...])` items as light-DOM `.nav-icon-btn`s in the nav's toolbar slot (the kit's "…" overflow picks them up on a phone), fills the account menu and the workspace switcher, sets the phone ribbon's `compact-title`, and mounts the router — registering its `hashchange` → `fb.toolbar.clear()` listener *before* `sac.router.mount` adds its own, so the toolbar is empty when the next view connects (keep that order). **Views use light DOM** (kit classes + tokens apply); **components use Shadow DOM**. **Corners are only the kit's three radii** — `--radius-s` (2px, tiny marks), `--radius-m` (4px: controls, inputs, list rows, pills), `--radius-l` (6px: panels, cards, dialogs); no raw `border-radius` px and no 999px pills (50% for true circles is fine). A list pane has one gutter: search field, header buttons and highlighted rows end the same distance from the edge (guarded by `Notes_LongTitle_NeverRunsUnderRowActions_Test`). Theme via the kit's tokens on `:root` (`--accent`, `--accent-warm`, `--danger`, `--hover`, `--accent-tint`, `--field`, `--border`, `--text-muted`, `--ok`…) — no raw colours in new code. **Mobile:** notes/todos/calendar sit on `<sac-split collapse>` (one pane at a time ≤768px: `split.show = "end"` on open, the split's back bar returns); row actions use the kit's `.reveal-on-hover`/`.hover-reveal` + `.icon-btn` (always shown + 44px hit area on touch); view heights are `calc(100dvh - 50px - env(safe-area-inset-top))`. Guarded by the phone tests in `Fishbowl.Ui.Tests`. Every component is the kit's `sac-*` — **`js/components/` is gone; there are no `fb-*` components**. What the kit has no component for is app code built from kit parts: the workspace switcher is a `<sac-menu slot="context">` filled by `shell.js`, tag management is `fb.tagManager` (`js/lib/tag-manager.js`, a `<sac-window>`), tags in the editor are `<sac-chip-input>` (the view feeds `suggestions` from `fb.tags` and persists `sac:create`), the filter strip is `<sac-chip>`, confirms are `sac.dialog`. Don't add an `fb-*` element — build from kit parts, or file the missing piece upstream. Kit menus force item `display`/`background`/`color` with `!important`: `hidden` doesn't hide an item (add/remove it instead, sacrvm-appkit#1) and colour can't mark the active one (use an icon). The markdown editor is **`<sac-md-editor>`, vendored verbatim** from `SACRVM/sac-md-editor` at `js/vendor/sac-md-editor/` (pinned commit in the `VERSION` file beside it) — never edit it in place; fixes go upstream, updates replace the file, and `MdEditorTests` is the verification step after a bump. It uses the kit's `marked`/`purify` (`kit/js/vendor/`) and fires native `input`/`change` plus `history-change`. `fb.icons.register(name, path)` extends Fishbowl's icon set, `sac.icons.register` the kit's (`js/lib/icons.js` bridges the `fish` brand mark). `/login` and `/setup` stay server-rendered on `app.css`. Component spec: `docs/superpowers/specs/2026-04-19-ui-foundation-design.md`.

**Context is URL-driven** (personal vs space workspace). `#/notes` = personal, `#/space/<slug>/notes` = space. That is the kit's `sac.scope`: `get()` returns `{ type: "root" }` or `{ type: "scoped", slug }` (**`root`/`scoped`, not user/space**), `set({ type: "scoped", slug })` / `set({ type: "root" })` switches, `hashFor()` keeps a link in the active workspace, and `sac:scope-changed` fires on every switch. `fb.api` builds its own paths from `sac.scope.get()` (`api.js` `ctx()`), **not** `sac.scope.endpoint()`: the kit reuses the singular hash prefix for data paths, the REST nesting is plural (`/api/v1/spaces/<slug>/…`). The router strips the space prefix for view lookup (`sac.router.currentResource()`) so one view registration serves both workspaces. Hrefs that should be sticky across contexts (nav items, hub tiles, brand) wrap through `sac.scope.hashFor()`. Switcher: `<sac-menu id="fb-context" slot="context">` inside the shell's `<sac-nav>`, filled by `shell.js`; the context slot is separate from the toolbar slot `fb.toolbar` repaints, so the switcher survives per-view toolbar paints and stays visible on a phone. Its space list reloads on `fb:spaces-changed`, which `fb.api.spaces.create/delete` fire — no view has to tell the shell; a deleted active space falls back to personal. Space context tints the switcher with `--accent-warm` so edits to shared data are unmissable. **Accent colours** (system schema **v9**: `spaces.color`, `users.accent`, plus `users.date_format`) are kit palette slot names (`TagPalette.Slots`, `fb.tags.SLOTS`) or null for the default: a user's accent (profile window, `PATCH /api/v1/me`, cookie-only) replaces `--accent`; a space's colour (spaces settings: the row's colour dot opens a picker dialog; `PATCH /api/v1/spaces/<slug>`, owner-only) takes over the whole UI while that space is active — `--accent` and `--accent-warm` both become it; a space without a colour keeps the personal accent. `shell.js` sets both inline on `:root` so the derived tokens follow; pickers are `<sac-swatch-grid>` via `fb.accents`. `GET /api/v1/me` is an explicit projection — the `User` record's password hash/salt never leave the server. `fb.tags` cache invalidates on `sac:scope-changed`.

**UI smoke test (`Fishbowl.Ui.Tests`)** launches `Fishbowl.Host` as a real subprocess on a free port for Playwright (not `TestServer`). A gated bypass (`FISHBOWL_PLAYWRIGHT_TEST` env + `Testing` environment) injects a test user. **Never set `FISHBOWL_PLAYWRIGHT_TEST` outside that fixture.**

**MCP surface** at `POST /mcp` — JSON-RPC 2.0 over Streamable HTTP, Bearer-auth only. Eight tools in `Fishbowl.Mcp.Tools/*` grouped by domain: notes (`search_memory`, `remember`, `get_memory`, `update_memory`, `list_pending`), contacts (`list_contacts`, `find_contact`), events (`list_events`). Each implements `IMcpTool` with a `RequiredScope`; `ToolRegistry` lists them for `tools/list`. MCP writes pass `NoteSource.Mcp` → `NoteRepository.ApplySourceTags` auto-adds `source:mcp` + `review:pending`. Human edits (cookie path) strip `review:pending` (approval by editing). **Secret-strip invariant:** every note response runs through `SecretStripper.StripNote` — `:::secret`…`:::end` blocks and `content_secret` blobs must never cross the MCP wire. Enforced by `SecretStripInvariantTests`.

**Hybrid search** (`HybridSearchService` in `Fishbowl.Data.Search`) blends sqlite-vec cosine distance (70%) with FTS5 bm25 (30%), each min-max normalised over a 50-candidate pool. `search_memory` tool always calls it; a `degraded: true` flag surfaces on the response when the embedding model isn't ready yet and ranking falls back to FTS-only. FTS query tokens are split on non-alphanumeric then prefix-matched with `AND` — matches how FTS5's default tokenizer indexes hyphenated identifiers. Lives in `Fishbowl.Data.Search` (not `Fishbowl.Search`) because it needs `DatabaseFactory`, and the dep direction forbids `Fishbowl.Search → Fishbowl.Data`; same reason `SqliteVecLoader` is in `Fishbowl.Data`.

**Embeddings:** `MiniLmPipeline` (ONNX Runtime + `Microsoft.ML.Tokenizers.BertTokenizer`) produces 384-dim L2-normalised float vectors for `sentence-transformers/all-MiniLM-L6-v2`. `ModelDownloader` pulls `model.onnx` + `vocab.txt` from HuggingFace on first start, SHA-256-pinned for the LFS-stored model. `EmbeddingInitializer` (`IHostedService`) runs the download detached. Callers on the hot path catch `EmbeddingUnavailableException` and degrade — `NoteRepository.UpsertEmbeddingAsync` logs and continues, `HybridSearchService` flips to FTS-only. `IEmbeddingService` lives in `Fishbowl.Core.Search` so `NoteRepository` can depend on it without a reverse-dep into `Fishbowl.Search`.

**vec_notes sync.** User DB v4 adds `vec_notes` (sqlite-vec virtual table, `FLOAT[384]`). Every `NoteRepository` write embeds `title + stripped content + tags` and writes the blob in the same transaction as `notes` + `notes_fts`. sqlite-vec's vec0 doesn't honour `INSERT OR REPLACE` as a true replace — use **DELETE then INSERT** explicitly. On delete, remove from `vec_notes` BEFORE `notes` (same pattern as `notes_fts`). Text fed to the model is always secret-stripped — a vector built from secret content would let semantic search surface notes on hidden text, violating the same invariant as the MCP wire.

**`POST /api/v1/search/reindex`** (cookie-only) triggers `NoteRepository.ReEmbedAllAsync` — iterates every note in the resolved context, re-runs the embed+DELETE+INSERT in one transaction, returns `{ processed, failed }`. Bearer requests get 403. Mirrored at `/api/v1/spaces/<slug>/search/reindex` for the space workspace. Used on model upgrade or the first time embeddings become available for a pre-existing personal DB.

**`GET /api/v1/search?q=…&limit=…&includePending=…`** is the CONCEPT.md hybrid search over notes: `HybridSearchService` blends sqlite-vec cosine distance with FTS5 bm25 and returns ranked hits + a `degraded: true` flag when the embedding model isn't ready yet. Response shape matches the MCP `search_memory` tool so clients can swap transports. `limit` is clamped to 1–100. Scope: `read:notes`. Space variant at `/api/v1/spaces/<slug>/search`. Notes-only for now; contact-scoped search stays on `/api/v1/contacts/search` until a unified ranker exists.

**`GET /api/v1/export/db`** (cookie-only) streams the authenticated user's SQLite file as a download via SQLite's online backup API — safe under concurrent writes, no lock, no corruption. `Content-Type: application/vnd.sqlite3`, `Content-Disposition: attachment; filename="fishbowl-<userId>-<yyyyMMdd>.db"`. Bearer requests get 403 (wholesale DB export isn't an agent action). The space variant `/api/v1/spaces/<slug>/export/db` is **owner-only** (`CanDeleteSpace`), not just any member: walking off with the whole space DB file is a terminal action, on par with space deletion. Implementation in `ExportApi.cs`; backup routes through a temp file and buffers into memory for the response (personal DBs stay small).

**Events** live at `/api/v1/events` (personal) and `/api/v1/spaces/<slug>/events` (space). CONCEPT.md § Calendar — "A calendar that belongs to you." `Event` model carries `Title`/`Description`/`StartAt`/`EndAt`/`AllDay`/`RRule`/`Location`/`ReminderMinutes`/`ExternalId`/`ExternalSource` + ULID + created_by + timestamps; the schema is the original `events` table from user DB v1 so no migration was needed. Scopes: `read:events`, `write:events`. List takes optional `?from=…&to=…` as an ISO-8601 half-open range; the repo stores `start_at` as ISO-8601 so lexical string comparison gives the right temporal ordering. **Range reads expand RRULE**: `GetRangeAsync` fans supported rules (see `Fishbowl.Core.Util.RRule`) into per-occurrence clones flagged `IsRecurringInstance` — same `Id` as the master, so a write against an instance's id edits the whole series; out-of-subset rules degrade to the master event. `GetAllAsync`/`GetByIdAsync` stay master-only. JSON gotcha: the `RRule` property serializes as **`rRule`** (Web-defaults camelCase keeps the second capital), the frontend reads/writes that name. `DeleteAsync` cascades the matching `reminders` rows (reminders FK events.id and are ephemeral). Read-only MCP via `list_events` (scope `read:events`) — supports an `upcoming_days` shortcut or an `from`+`to` ISO range (both get expansion via `GetRangeAsync`). Write tools deliberately not exposed: agents scheduling on your calendar has sharper consequences than agents remembering a note. **Calendar UI** at `#/calendar` (`fb-calendar-view.js`): Monday-first month grid + agenda pane; editor swaps in for the grid with title/all-day/start/end/reminder/repeat-preset/location/notes; new events are client-side drafts (POST happens on first save with a title — server rejects empty titles); opening a recurring instance loads the master via `GET /events/{id}`; works in both workspaces through `fb.api` (scope-aware paths).

**Contacts** live at `/api/v1/contacts` (personal) and `/api/v1/spaces/<slug>/contacts` (space). CONCEPT.md § Contacts: "Not an address book. A living record of the people who matter." `Contact` model carries `Name`/`Email`/`Phone`/`Notes`/`Archived` + standard ULID + timestamps. Storage: user/space DB schema v5 adds `contacts` + `contacts_fts`. No secret-strip layer — there's no encrypted column on contacts, hence nothing to strip. Scopes: `read:contacts`, `write:contacts`. `ContactRepository` mirrors the `NoteRepository` pattern (FTS rowid mapped via `(SELECT rowid FROM contacts WHERE id = @Id)`; delete FTS before the row). `SearchAsync` uses the same prefix-match-AND tokenizer as `HybridSearchService` so hyphenated queries don't get parsed as FTS5 NOT operators; exposed at `/api/v1/contacts/search?q=…` and over MCP as `find_contact`. `list_contacts` MCP tool does the plain listing. No UI wired yet — backend-only until the editor shape lands.

**Administration** (phase A1; spec `docs/superpowers/specs/2026-09-26-admin-design.md`). Three roles: a user owns their personal workspace, a space owner their space, the **admin** (`users.is_admin`) the instance — approving accounts and system settings, **never reading content** (no admin route returns notes, files or secrets; `AdminUsersApiTests.AdminRoutes_NeverReturnContent` guards it). System schema **v11**: `users.state` (`UserStates`: pending/active/disabled/blocked, existing rows active), `quota_bytes` (stored at approval; enforcement arrives with the Files data lifecycle), `approved_by/_at`, `last_sign_in_at`; `messages` (the system inbox) and `admin_audit` (actor/action/target **ids only**). **Every sign-in goes through `Fishbowl.Api.Accounts.AccountGate`** (Google's `OnTicketReceived` and `/api/auth/login` + change-password): blocked/disabled refuse (login page shows `?authError=`); with no active admin the signing-in active account becomes admin (Google-only installs, pre-v11 installs); a new identity is checked against `Auth:AllowedEmailDomains` (new accounts only) and `Auth:SignUp` — `approval` (default) creates a **pending shell** + one `user.pending` message per admin, `open` activates, `closed` refuses. `AccountStateMiddleware` (right after `UseAuthentication`) re-reads the state **per request**: pending reaches only `/pending` (server-rendered `pending.html`), `GET /api/v1/me` (carries `state`) and sign-out — everything else 403 `{error:"pending"}` / redirect; disabled/blocked drop the cookie and get 403 `{error:<state>}` (Bearer keys too) at the next request. Second wall: `DatabaseFactory` throws `InactiveAccountException` rather than create a personal DB for a registered non-active account; the scheduler iterates `ListActiveUserIdsAsync`. Admin API (`AdminApi.cs`, cookie + `IsAdmin`, Bearer 403): `GET /api/v1/admin/users` (metadata + `signUp` + `defaultQuotaBytes` from `Files:DefaultUserQuotaBytes`), `POST …/users/{id}/approve` (`{ quotaBytes?, makeAdmin? }`, 409 `not-pending`), `/reject` (deletes the shell, may ask again), `/block` (not yourself; `last-admin` 409), `/unblock` (unapproved → pending, approved → active); every admin write — incl. import, reset-password and config set/clear — is one `admin_audit` row. **Messages** (`MessagesApi.cs`, cookie-only): `GET /api/v1/messages` (`?unread=true`; for admins the server adds who a `user.pending` is about at read time — rows never copy names), `GET …/unread-count`, `POST …/{id}/read`; acting on a request resolves it (`done_at`) for every admin. System messages only — no chat. UI: the envelope `#fb-messages-btn` (badge = unread, refreshed on `fb:messages-changed`, navigation, every minute) opens `#/messages` (`fb-messages-view.js`, inline Approve with a GB quota field / Reject / Block); `#/admin/users` (`fb-users-admin-view.js`) is **registered only after `/me` says admin** (`fb.accounts.registerAdminRoutes`), so for everyone else it's in no nav, palette or route table; shared flows live in `js/lib/accounts.js` (`fb.accounts`). The kit has no mail icon — `kit-config.js` registers `mail`. Recovery: `tools/set-admin <userId|username>`. The Playwright fixture's injected user is an active admin.

**Files** (backend phase 1 + UI phase 2; spec `docs/superpowers/specs/2026-09-26-files-app-design.md`). Real files with real names in a real tree: `users/<id>/files/` and `spaces/<id>/files/` beside the context DB (created lazily on first write, so cold import moves them) — **the disk is the truth**. User/space schema **v9** adds only what the file system can't hold: `file_index` (rebuildable reconcile baseline + sniffed type / SHA-256 cache, valid while size+mtime match), `file_changes` (the journal; `seq` is the sync cursor), `file_trash` (bookkeeping for `files/.trash/<ulid>/<name>`) and a one-row `file_state` (epoch, compaction floor, case rule). **`IFileService` / `Fishbowl.Data.Files.FileService` is the single entry point**; only `DiskFileStore` touches `files/`, only `FilePathResolver` combines paths. Every mutation runs under a per-context lock: disk op, then one transaction (index + journal); a crash in between is repaired by reconcile (per folder on list, full tree before feed/snapshot throttled by `Files:ReconcileIntervalSeconds`, daily in `FilesMaintenanceService` which also sweeps stale `.~fb-*.part`, purges trash and compacts the journal). **Path safety:** wire paths are relative and `/`-separated; no leading slash, `..`, `\`, drive/UNC syntax, reserved `.trash` (root) or `.~fb-*`; links (symlinks, junctions, reparse points) are listed as `kind: link` and never followed; names follow **the host's rules** (`Fishbowl.Core.Files.FileNameRules`: Windows devices/forbidden chars/trailing dot/8.3 aliases, macOS `:`, UTF-8 byte length on Linux, plus a floor of no control/bidi chars) — a 400 `{ error: "invalid_name", rule, segment, message }`; case sensitivity is probed per volume (`FileVolume`). Uploads are a raw-body `PUT …/content` with `X-Fishbowl-Upload: 1` and **required** `If-None-Match: *` / `If-Match` (else 428, mismatch 412), streamed through a hidden temp file in the target folder + `IncrementalHash`, then renamed; an aborted upload leaves nothing. ETag = `<size>-<mtime ticks>`. Downloads stream with Range; every content response is `nosniff` and — unless `?inline=1` on a sniffed raster image/audio/video/plain text — `attachment` with a `sandbox` CSP; a sniffed `%PDF-` opens inline in its own tab under its own CSP (no sandbox). Type is sniffed from the first 4 KB (`FileSniffer`), never trusted from the client; HTML/SVG/XML/JS are never inline whatever their name. Limits are `system_config` keys with defaults (`Files:MaxFileBytes` 2 GiB, `Files:QuotaBytes` 20 GiB, `Files:InstanceCapBytes` 0, `Files:MinFreeBytes` 1 GiB → 507, `Files:TrashRetentionDays` 30, `Files:JournalRetentionDays` 90) read per request. Routes (`FilesApi.cs`, personal `/api/v1/files` + space mirror `/api/v1/spaces/<slug>/files`): `capabilities`, `list`, `stat`, `content` (GET/PUT), `folders`, `move`, `copy`, `DELETE ?path=` (trash; `&permanent=1` cookie-only), `trash` (+ `/{id}/restore`, `DELETE /trash/{id}`, `DELETE /trash` cookie-only), `usage`, `changes?cursor=` (410 `cursor_expired` on a foreign epoch / compacted / ahead cursor → take a `snapshot`, NDJSON), and cookie-only `POST /api/v1/files/transfer` (personal ↔ spaces). Scopes **`read:files` / `write:files`** (never added to existing keys); a space-bound key only reaches its own space's files. Logs carry a short path hash, never names.

**Files UI** (`#/files/*`, `fb-files-view.js`) is a two-pane commander built only from kit parts: two `<sac-file-browser multiple no-thumbnails>` side by side in a flat 50/50 grid (no splitter, no frames or corners — one hairline; header and footer share `--fv-bar-h`; the active side shows only as an `--accent` hairline under its header; selection is a quiet `--hover` row via `::part(selected|cursor)`), a footer per column with `<sac-tab-group>` tabs then the status as plain text (left: *Browse*; right: *Browse* / *Preview* / *Properties* — Alt+P / Alt+I, both following the left pane's cursor; a phone shows only *Browse*), `<sac-shortcut-bar group="Files">` for the chords, `<sac-quick-look>` for the preview and the quick-look window (Space / Enter / double-click, a maximised `<sac-window>`, ←/→ walk the folder), `<sac-drop-zone overlay>` per pane for uploads, `<sac-progress>` beside the bar. **Keys are modern, no F-keys** (spec decision 13): Alt+N/R/C/M/P/I/U/S, Alt+1/Alt+2 (pane workspace menus), Delete (trash, no question) / Shift+Delete (asks, then permanent), mod+C/X/V (clipboard across panes and workspaces), mod+F (filter the folder), Tab (switch pane while a list has focus), `?` (sheet). The **left pane is the app's workspace and lives in the URL** — a kit prefix route: `#/files/<folder>` / `#/space/<slug>/files/<folder>`; walking folders never remounts the view (it listens for `sac:route` and repaints the toolbar, which `shell.js` clears on every hash change); picking another workspace for the left pane is a scope switch. The right pane's workspace + folder sit in `sessionStorage` (`fb.files.right`). The store is `fb.filesStore({ workspace })` (`js/lib/files-store.js`) — the kit's store contract over `fb.api.files.in("personal" | "space:<slug>")` (one level per request via `entries()`, stats cached; a `.folder` marker write = `POST /folders`); `fb.api.files` without `.in()` follows `sac.scope`. The view takes over delete and rename (`sac:request-remove` / `sac:request-rename` → `preventDefault`) so refusals become toasts. **Everything that crosses panes — Alt+C/Alt+M, drag and drop, paste, the phone's Copy to… / Move to… destination picker — is one `fb.api.files.transfer`** (`/files/transfer` works within a workspace too); a `name_exists` item asks **Replace / Keep both / Skip** (+ "for the rest too"), and uploads ask the same on a 412 (Keep both finds `name (n).ext`). Uploads go through XHR for progress (`fb.api.files.in(ws).upload`, `parents=1`, folder drops keep `relativePath`). No dead buttons: a read-only space pane gets `readonly` on its browser and no write item in the bar, the toolbar or as a copy/move target. The trash is a `<sac-window>` per workspace (Restore — as a copy on a clash —, delete permanently, empty). `FilesTests` in `Fishbowl.Ui.Tests` cover the keys, cross-workspace transfer with a clash, upload clashes, preview/quick look, the read-only pane, the phone, and that full Chromium really renders an inline PDF under `FilesApi`'s headers (the headless shell can't — that test launches `Channel = "chromium"`).

**Space-nested API shape.** Every resource the SPA shows in a workspace has a cookie-scoped personal path **and** a space-scoped nested path, and they share the handler logic (just a different `ContextRef`): notes, tags (CRUD + color + rename), todos (CRUD), contacts (CRUD, reject readonly writes), search/reindex, export/db (owner-only). Space routes live in `SpacesApi.cs`, go through `ResolveSpaceAsync` (validates membership + Bearer-context match), and reject `role == Readonly` on writes via `SpaceRoleExtensions.CanWrite()`. Bearer tokens bound to a space can only hit their own space's paths; a personal-scope token on a space URL is 403 even when the human behind it is a member — the token's context, not the user's membership, is the authoritative scope.

**Dev ports.** In Development the host binds **both** `https://localhost:7180` **and** `http://localhost:7181`, and `UseHttpsRedirection` is skipped. The HTTP port is for programmatic clients (Claude Code's MCP over HTTP, `curl`) that don't want to deal with the self-signed dev cert; the HTTPS port stays the primary URL for browser + logged-in flows. A dev-only request-trace middleware logs `>> METHOD /path auth=… accept=…` and `<< … status scheme=…` on `/mcp` + `/api/*` so you can see what an MCP client is actually sending. Production: both the HTTP bind and the trace logger are skipped by `app.Environment.IsDevelopment()` gates.

**Prod ports.** Production binding is driven by what's in `system.db`. With ACME configured (`Acme:Domains`/`Acme:Email`/`Acme:AcceptTos` all set), `Program.cs` binds `0.0.0.0:80` + `0.0.0.0:443` and `UseHttpsRedirection` is active. Without ACME — fresh install or LAN-only deployment — Program.cs binds **`0.0.0.0:80` HTTP-only** so the operator can reach `/setup` on first boot, and `UseHttpsRedirection` is skipped (nothing's listening on 443 to redirect to). If `urls` is set in configuration — via `ASPNETCORE_URLS` env var or `--urls` CLI arg, both feed the same key — the fallback skips and Kestrel uses those URLs (operator escape hatch for a non-80 port; also how `PlaywrightFixture` pins its tests to a free loopback port without hitting the prod default). The "post-ACME" → "post-restart-binds-443" transition is why /api/setup returns `restartRequired: true` when ACME fields change.

**Dev tools under `tools/`.** `mint-dev-key` issues an API key directly against `ApiKeyRepository` without a browser session — supports `--scopes`, `--context user|space`, `--context-id <slug>`; token on stdout, metadata on stderr. `reindex-dev` calls `NoteRepository.ReEmbedAllAsync` against the disk (bypasses the cookie-only HTTP endpoint). `seed-dev-data` populates notes/todos/contacts in a context for quick UI + MCP iteration; sentinels (`seed:dev` tag on notes, `[seed-dev] ` prefix on contacts/todos) make it idempotent, `--force` overrides. `init-space <slug>` is the per-space bootstrap: creates (or reuses) a space with the given slug, mints a space-scoped API key with all read/write scopes by default, prints the bearer on stdout + a status banner on stderr. Stays agnostic about who consumes the bearer — downstream agent-CLI wiring (credential storage, MCP config) lives in the consumer's docs, not Fishbowl's. `snapshot-data` hot-backs-up the whole data dir via SQLite's online backup API to `fishbowl-backups/snapshot-<ts>/` — safe under live writes, intended for cron'd operator runs (see tools/snapshot-data/README.md). `set-config <key> [<value>]` writes a single `system_config` key (value from stdin when omitted, for secrets) — the post-setup side door for ACME/Discord/logging knobs and the digest opt-in (`Digest:Enabled`, `Digest:Hour`). `set-admin <userId|username>` makes an account an active admin — the lock-out recovery path. All read `system.db` via the real `DatabaseFactory`, share exit codes, and `tools/` is outside the product solution. `.mcp.json` at repo root (gitignored) holds Claude Code's local MCP config pointing at `http://localhost:7181/mcp`; regenerate the token with `mint-dev-key`.

**Per-space agent integration.** Any agent CLI that wants its own Fishbowl memory namespace gets its own **space** — file-boundary isolation, role-based membership, space-scoped MCP routes. `tools/init-space <slug>` bootstraps the space plus a space-scoped key. The bearer token's `fishbowl_context_type=space` claim carries the scope; there is no `project_id` MCP tool argument and no `X-Project` header — the token *is* the scope. The host also serves `/s/<slug>` as a 302 to `/#/space/<slug>/notes`, a thin URL-alias convenience for downstream link templates that prefer not to construct the SPA hash route directly.

**Desktop apps — server side** (`Fishbowl.Core.Desktop`, `DesktopRepository`, `DesktopApi`; spec `docs/superpowers/specs/2026-09-26-desktop-apps-design.md`). User/space schema **v10**: `desktop_tiles` (a workspace's tile arrangement: position REAL, size, palette colour, hidden) and `desktop_apps` (installed apps: the manifest the owner's browser read, origin, entry URL, SRI pin, mode, granted capabilities). `/api/v1/desktop` + `/api/v1/spaces/<slug>/desktop`: **cookie-only** (Bearer 403 — installing code is never an agent's act), members read, **only the workspace owner writes** (sharing a space shares its apps). **The server never fetches a foreign URL**: `AppManifestValidator` checks what was posted (https origin, loopback http for dev; entry on the manifest's own origin; `permissions` ⊆ files/identity, `connect` = exact https origins, `opens` = MIME/ext). Two modes: `sandboxed` (default, needs the entry's SRI hash — new code re-pins via PATCH) and `trusted` (same-realm, no pin, **personal only**). Admin policy keys `Apps:Install` / `Apps:Trusted` (everyone|admins|off; a space owner installs unless `off`), `Apps:AllowedOrigins`, `Apps:StoreOwners`, `Apps:StoreTopic`. An app's data lives in Files at `AppDataFolders.For(name, id)` (`Apps/<name>`); `DELETE …/apps/{id}` keeps it unless `?purgeData=true`. `GET /apps/frame/{user|space}/{id|slug}/{appId}` serves a sandboxed app's frame document (kit + `/js/lib/app-guest.js` + the pinned entry with `integrity`) under `FrameCsp.Build` (per-app, `connect-src` = declared origins or `'none'`); anything it can't serve is 404. Origins pass `AppOrigins.IsSafe` before they reach a header.

## Conventions

- **Dapper snake_case via `DapperConventions.Install()`** in `DatabaseFactory` static ctor — `created_at` → `CreatedAt` works automatically. `JsonTagsHandler` handles `List<string>` ↔ JSON for `notes.tags`. Use `QueryAsync<T>`, never `QueryAsync<dynamic>` with manual mappers.
- **FTS5 + vec_notes must stay synced.** `notes_fts.rowid` maps to `notes.rowid` via `(SELECT rowid FROM notes WHERE id = @Id)`. On delete, remove from `vec_notes` AND `notes_fts` BEFORE `notes`. Tags are space-joined string (not JSON).
- **Logging via `ILogger<T>?` defaulting to `NullLogger<T>.Instance`** so tests can construct objects directly. **Never log PII** (email, name, content, secrets, tokens). Sinks: console always, plus rolling daily file at `fishbowl-data/logs/host-{yyyy-MM-dd}.log` (Serilog) — file sink suppressed in `Testing` env so smoke fixtures don't accumulate temp artefacts. Retention + plain/JSON format read from `system.db` (`Logging:RetentionDays`, `Logging:Format`) via `BootConfig.LoadLogging` at boot; defaults are 7 days + plain text. Changing either needs a host restart (acceptable — ops don't retune logging hot).
- SQLite `DateTime` stored ISO-8601 (`.ToString("o")`); booleans as `INTEGER 0/1`; IDs are ULIDs.
- Secrets use `:::secret` markdown block + separate `content_secret BLOB` (client-encrypted). **Never include secret content in FTS, embeddings, or chat responses** — non-negotiable; enforced by `SecretStripper` on every MCP return path (it also strips labelled blocks, `:::secret <label>`).
- **Secret vault v2** (`js/lib/vault.js`, spec `docs/superpowers/specs/2026-09-25-secret-vault-design.md`): one random vault key per user encrypts every block (AES-GCM, AAD `<note id>|<index>`); the server stores only wrapped copies of it in `vault_keyslots` (user DB **v7**) — a passphrase slot (PBKDF2-SHA256 600k, salt in the slot) and a recovery slot (24 BIP-39 words → HKDF; list vendored at `js/vendor/bip39/english.txt`, **hash-pinned in vault.js** — never edit it). Unlocked key is non-extractable and memory-only; auto-lock after 15 min. `/api/v1/vault` is cookie-only + personal-only (Bearer 403). `content_secret` must be a `{ "v": 2, blocks }` envelope (`SecretEnvelope`), and **spaces hold no secrets**: `NoteRepository` refuses any secret in a space context on every write path (400 via `ResourceValidationKind.Invalid`; `ValidationResults.From` maps Invalid → 400, SizeLimit → 413). Passkeys are a third slot kind: WebAuthn PRF output → HKDF (`prf-hkdf-sha256` kdf, salt per slot), probed at runtime (`fb.vault.passkeySupported()`), offered at setup and first in the unlock dialog; a vault always keeps a passphrase or recovery slot (server 409 `last-recoverable-slot`). **Settings → Secrets** (`#/secrets`, `fb-secrets-settings-view.js`) lists the slots and runs add passkey / change passphrase / new recovery key (+ printable emergency kit) / rename / remove through `fb.vault` — each asks for a way in again, because the session key is non-extractable. Auto-lock minutes are a user setting (`users.vault_auto_lock_minutes`, system **v10**, `VaultSettings.AutoLockChoices`, via `PATCH /api/v1/me`). WebAuthn needs a domain, not an IP: the passkey UI test uses `localhost`.
- **Dates go through `fb.format`** (`js/lib/format.js`), never `toLocale*(undefined)` or native date/time inputs: browsers only expose the UI *language*, never the OS regional format (by design, anti-fingerprinting), so English Chrome would show US dates. The format is a user setting (profile → Date & time format; `users.date_format` ∈ `DateFormats.Names` iso/de/uk/us, null = ISO; `PATCH /api/v1/me` is partial). Date inputs are the kit's `<sac-date-field>` + `<sac-time-field>`, driven page-wide by `sac.regional` (`fb.format.set` maps iso/de/uk/us → `iso`/`dmy.`/`dmy/`/`mdy/` + h23/h12); `fb.format.attachInput(input, { time })` swaps a placeholder `<input>` for the pair, both `size="regular"` (the date field keeps the id and fires `change` for both), `readInput` → Date|null (empty time = 09:00), `writeInput`, `setInputTime` (all-day). A format change remounts the current view.
- **Todo order is the user's**: `todos.position` (user DB **v8**, REAL). Create appends (`MAX+1`), a PUT without `position` keeps it, a drag in the todo list (`sac.sortable`) writes one row — the midpoint of its new neighbours. The list sorts open before done, then by position; due dates don't reorder.
- **System tags** carry three flags (`is_system`, `user_assignable`, `user_removable`) — set in `Fishbowl.Core.Util.SystemTags.Seeds`. Current seeds: `review:pending` (removable by user), `source:mcp` (locked). Rename/delete of `is_system=1` rows rejected in `TagRepository`.
- Modding rule: "disk file wins, else default" — components/styles/scripts/templates only. `fishbowl-mods/` is currently the dev overlay (junctions into `Fishbowl.Data/Resources`); see `docs/slimming-plan.md` for its pending fate.

## Husky launcher

The host attaches to [Husky](https://github.com/SACRVM/husky) when the launcher hosts it (`HuskyClient.AttachIfHostedAsync` returns `null` under `dotnet run` / debugger, so dev is unaffected). Husky-driven shutdown forwards to `app.StopAsync(ct)` so hosted services (Discord bot, embedding initializer, ACME renewal) drain cleanly before the binary swap. End users run `Husky --repo SACRVM/the-fishbowl --asset 'Fishbowl-{version}-<rid>.zip'`; Husky reads `husky.config.json` from the repo root for `name` + `executable` + timing knobs (currently Windows-pathed; Linux/Mac users override `executable` in their local config). Husky preserves anything outside the update package, so `app/fishbowl-data/` survives upgrades.
