# CLAUDE.md

Guidance for Claude Code in this repository.

## What this project is

Self-hosted personal memory + assistant. **`CONCEPT.md` is the target spec** — external sync, scripting, the full plugin ecosystem are still future design. Implemented projects: `Fishbowl.Core`, `.Data`, `.Api`, `.Host`, `.Mcp` (8 tools), `.Search` (hybrid via `Fishbowl.Data.Search`), `.Bot.Discord` (real bot, 25 tests), `.Scheduler` (event-reminder MVP, 5 tests). Still empty shells: `Fishbowl.Sync`, `Fishbowl.Scripting`. Align with CONCEPT.md — don't invent a different architecture. See `CONTRIBUTING.md` and `docs/superpowers/` for active work.

## Working style — adaptive programming

Find the closest existing solution and **extend it**, don't parallel it. Almost-fits → add overload/option/partial. Genuinely wrong → say so and migrate callers. **Never silently diverge.**

- **HTTP endpoints**: `MapXxxApi()` extensions on `IEndpointRouteBuilder`; resolve the request's scope via `McpContextClaims.Resolve(user)` → `ContextRef` (User or Space), call a repository. Gate with `.RequireScope("read:notes")` etc. — cookie principals bypass scope; Bearer principals must match. Routes under `/api/v1/`.
- **Repositories**: interface in `Fishbowl.Core.Repositories`, impl in `Fishbowl.Data.Repositories`, `AddScoped`. Access via `DatabaseFactory.CreateContextConnection(ctx)` or `CreateSystemConnection()`. The legacy `CreateConnection(userId)` is a `ContextRef.User`-alias kept for cookie callers.
- **Multi-step writes**: `_dbFactory.WithContextTransactionAsync(ctx, async (db, tx, ct) => …)` — see `NoteRepository` for `notes` + `notes_fts` syncing.
- **Schema changes**: add `ApplyVN` in `DatabaseFactory`, bump `PRAGMA user_version`. No EF Core, no migration runner.
- **UI resources/scripts/templates**: `IResourceProvider.GetAsync(path)` only (disk → DB → embedded). Never direct file I/O.
- **Plugins**: implement `IFishbowlPlugin`, register via `IFishbowlApi.AddBotClient/AddSyncProvider/AddScheduledJob` (`Fishbowl.Core.Plugins`).
- **Configuration**: in `system.db` via `ISystemRepository.Get/SetConfigAsync` — never `appsettings.json`, never env vars for runtime config.
- **Frontend backend calls**: `fb.api.notes.list()` etc. — 401s auto-redirect to `/login`. Never `fetch` directly from views/components.

## Architecture

**Dependency direction:** `Host → Api/Bot.Discord/Sync/Scheduler/Scripting → Data/Search → Core`. `Fishbowl.Host` is the **only publish target**; everything else is a library. No cycles, no upward refs.

**One `DatabaseFactory` (singleton), three DB locations:**
- `CreateSystemConnection()` → `fishbowl-data/system.db` — `users`, `user_mappings`, `spaces`, `space_members`, `api_keys`, `system_config`.
- `CreateContextConnection(ContextRef.User(userId))` → `fishbowl-data/users/{userId}/personal.db` — notes, events, todos, tags, notes_fts, vec_notes. Folder-per-context: dropping the whole `users/{userId}/` folder onto another instance moves the user's data atomically (cold import).
- `CreateContextConnection(ContextRef.Space(slug))` → `fishbowl-data/spaces/{spaceId}/space.db` — identical schema to user DBs. Folder is keyed by the space's ULID, not its slug — slug can change (rename) while the folder stays put. `ResolveSpaceAsync` translates slug→id before opening.
- Legacy flat user layout (`users/{id}.db`) auto-migrates to `users/{id}/personal.db` on first open via `MigrateLegacyLayoutIfPresent`. The old `Team` primitive's on-disk layout (`teams/{id}/team.db` and ancient flat `teams/{id}.db`) is renamed wholesale to `spaces/{id}/space.db` by `MigrateTeamsFolderToSpaces`, which runs once at `DatabaseFactory` construction. Both are idempotent and never overwrite a pre-existing new-path file. The `Team`→`Space` table/api_keys rename is system-schema **v8** (`ApplySystemV8`).

Lazy migrations keyed on `PRAGMA user_version`. Dapper raw SQL; IDs are ULIDs (`Ulid.NewUlid().ToString()`).

**sqlite-vec loaded on every context open.** `SqliteVecLoader.LoadInto(conn)` enables extension loading, calls `LoadExtension("vec0")`, then flips extensions back off. Binaries ship via the `sqlite-vec` NuGet package (v0.1.7-alpha.2 by roji + jeffhandley) — MSBuild drops them under `runtimes/{rid}/native/` automatically. System DB skips this (no vec tables there).

**Two auth schemes, one principal shape.** Cookie (Google OAuth; default) and ApiKey (Bearer `fb_live_…`). On first login, `Program.cs` creates a Fishbowl user, maps `(provider, providerId) → internalUserId`, adds a `fishbowl_user_id` claim. Bearer keys additionally carry `fishbowl_context_type` + `fishbowl_context_id` + one `scope` claim each — `McpContextClaims.Resolve(user)` collapses all of that to a single `ContextRef`. The cookie scheme forwards Bearer requests to ApiKey via `ForwardDefaultSelector`, so `.RequireAuthorization()` is scheme-agnostic. Data isolation is by file boundary, not row filtering.

**OAuth creds in `system.db`, not `appsettings.json`.** `GoogleOptions` binds against `ConfigurationCache` populated at startup by `ConfigurationInitializer : IHostedService`. `POST /api/setup` writes both DB and cache so changes propagate without a restart. Unconfigured options use sentinel `"placeholder"`.

**API/MCP paths return 401, not 302.** `OnRedirectToLogin` is overridden so `/api` and `/mcp` requests get `401` instead of redirect to Google — browsers following the redirect would ruin Bearer/MCP flows. OpenAPI doc at `/api/openapi.json`.

**`/setup` locked after config.** Once `Google:ClientId` is set, `GET /setup` and `POST /api/setup` return `404` (not 302 — harder to bypass). Validates: ClientId ends `.apps.googleusercontent.com`, ClientSecret ≥ 20 chars. No antiforgery (only responds when unconfigured).

**`IResourceProvider` serves the web UI and mods.** Three-tier: disk (`fishbowl-mods/{path}`) → DB (not yet wired) → embedded in `Fishbowl.Data.dll`. `MapFallback` handles non-API paths; unmatched `/api/*` short-circuits to 404 (so it doesn't serve `index.html`). The private `TryOpenEmbeddedStream` helper tries three path forms because MSBuild's `RecursiveDir` produces Windows-style paths on Windows — keep it.

**Plugins in isolated ALCs.** `PluginLoadContext` uses `AssemblyDependencyResolver` in a collectible ALC so `fishbowl-mods/plugins/` DLLs ship their own deps. `PluginLoader.LoadPlugins` runs at startup (`Plugins:Path`, default `fishbowl-mods/plugins`); failures logged and skipped.

**Discord bot** (`Fishbowl.Bot.Discord`) is the reference `IBotClient` impl, in-tree, not a sideloaded plugin. `DiscordBotHostedService` owns the `DiscordSocketClient` for the host's lifetime — Bulk-overwrites global slash commands on `Ready`, dispatches `SlashCommandExecuted` to `SlashCommandRouter` via a fresh DI scope per invocation, and defers immediately so the 3-second interaction deadline doesn't bite slow paths (`/search` hits the embedding model). DM-only invariant: guild invocations rejected hard at the dispatcher regardless of declared contexts. **Six commands** in `Commands/*Handler.cs`: `/help`, `/link <code>`, `/unlink`, `/remember`, `/search`, `/recent`. `/link` redeems one-shot codes from `IDiscordLinkRepository` (10-min TTL, atomic burn) and writes both `user_mappings (provider="discord", provider_id=<discord_user>)` and `notification_channels` so the DM channel is cached for future sends. `/unlink` is the inverse — deletes the mapping then removes the channel. Token bound from `system.db`'s `Discord:BotToken` via `ConfigurationCache` (same path as Google); empty/`"placeholder"` token → service no-ops with a warning so the host still boots on fresh installs. `/api/setup` accepts and validates `DiscordBotToken` (length + dot-separator shape) and flags `restartRequired: true` because the gateway connection binds at startup. `DiscordBotClient.SendAsync` resolves `notification_channels` → DM channel id → posts; `ReceiveAsync` is deliberately an empty stream (slash-commands not message events). Cold-DM fallback: when the cached channel id misses the gateway cache, looks up the mapped Discord user via `ISystemRepository.GetProviderIdForUserAsync(userId, "discord")`, fetches the user (gateway → REST), opens a fresh DM with `CreateDMChannelAsync`, and re-caches the new channel id so the next send hits the fast path. `SendAsync` is wired live: `Fishbowl.Scheduler.ReminderDispatcher` fires it on event-reminder triggers (see Scheduler section below). Search/recent return titles only — content never leaves the bot (even non-secret notes might be long, or the user might be on screenshare).

**Apps platform** (`Fishbowl.Core.Apps`, `Fishbowl.Mcp.Tools.Apps`, `AppsApi`). CONCEPT.md § Apps — mini-apps with their own SQLite, their own owner-declared schema, their own scope-gated MCP/REST surface. Each App nests under its owner (`users/<id>/apps/<appId>/app.db` or `spaces/<id>/apps/<appId>/app.db`); the apps registry table lives in the owner's user/space DB (user-schema v6), so dropping a space folder onto another instance moves the space **with** its apps atomically. `system.db` schema v7 widens `api_keys` to a third context type with paired `owner_type`/`owner_id` columns — the Bearer token *is* the App scope; there's no `app_id` argument on MCP calls. `McpContextClaims.ResolveApp(principal)` collapses the three claims into an `AppRef(ownerType, ownerId, appId)`. Owner-defined tables get **eight server-injected base columns** (`id` ULID, `title` NOT NULL, `author`, `created_at`, `last_modified`, `row_version`, `is_deleted`, `deleted_at`, `additional_data`) plus a mandatory `idx_<table>_is_deleted`. `additional_data` is a JSON ride-along, capped at 256 KB (ResourceValidationException → InvalidParams); the query DSL rejects filters on it explicitly. The DSL is MongoDB-style JSON (`$eq $ne $lt $lte $gt $gte $in $like $isNull $isNotNull` + `$and $or $not`), validated against the live schema and compiled to parameterised SQL via `QueryDsl.Compile`. Safety caps: depth ≤ 5, leaves ≤ 100, `$in` ≤ 50, `limit` ≤ 500 — caps return `QueryDslException` → InvalidParams. **Scopes** `app:read` / `app:write` / `app:admin` gate row reads, row writes, and DDL respectively (single-app-wide; no per-table or per-row scopes in MVP). **13 MCP tools** in `src/Fishbowl.Mcp/Tools/Apps/` (`app_list_tables`, `app_describe_table`, `app_create_table`, `app_alter_table`, `app_drop_table`, `app_create_index`, `app_insert`, `app_get`, `app_update`, `app_delete`, `app_restore`, `app_query`, `app_count`) join the existing `ToolRegistry`. REST mirror at `/api/v1/apps` — cookie-only lifecycle (`POST /`, `GET /`, `GET|PATCH|DELETE /{ownerType}/{ownerId}/{slug}`) + cookie-only key mgmt under `.../keys` + Bearer-or-cookie data plane under `.../tables`, `.../rows/{table}`, `.../query/{table}`, `.../count/{table}`. `{ownerType}` ∈ {user,space}; user owners use the user-id, space owners use the space-slug (resolved to ULID by `ResolveAppAsync` before any repository call — consistent with the space-folder rename invariant). DELETE uses `?confirm=<slug>` (minimal-API doesn't infer DELETE bodies) and drops the whole `app.db` folder. `tools/init-app <slug> --owner space:<slug>|user:<id>` bootstraps an app + mints an app-scoped key in one step; the bearer goes to stdout, status banner to stderr (same shape as `init-space`). App data **never** appears in `search_memory` / `list_pending` / hybrid search — they read from the owner DB, not app DBs. App keys never authorise `read:notes` / `write:notes` etc., so an app's agent stays sandboxed. Out-of-MVP follow-ups: per-table FTS5/vector index, triggers, cross-app reads, form-builder UI, slug rename, owner-cascade delete (currently a space with apps still deletes via `SpaceRepository.DeleteAsync`; the leftover `apps/` subfolder is operator-cleanup). Spec: `docs/superpowers/specs/2026-05-13-apps-platform-design.md`.

**Scheduler** (`Fishbowl.Scheduler`) runs as `IHostedService` and dispatches event reminders. Ticks every minute with a 30s startup delay; on each tick enumerates personal-context users via `ISystemRepository.ListUserIdsAsync`, opens each user's context DB, runs `IEventRepository.ListDueRemindersAsync(ctx, from, to, notAncient)` which selects events whose `start_at − reminder_minutes` falls in the half-open window. Catch-up window is 6h on first boot so a restart doesn't drop notifications that became due during downtime. The `notAncient` guard (start_at within past 24h) prevents a Monday-morning dispatcher from drowning in long-past triggers. For each due event the dispatcher checks `INotificationChannelRepository.GetAsync(userId, bot.Name)` against each registered `IBotClient` in order; first bot with an enabled channel wins. After a successful `SendAsync` it inserts a `reminders` row with `sent_at` set — that row is the dedupe latch for subsequent ticks (`IReminderRepository.GetSentEventIdsAsync`). **No record when delivery isn't attempted** (channel missing/disabled): the user might link Discord later, and we want the original reminder to still fire. Space-event reminders are deliberately out of scope for MVP — recipient semantics for shared events need a design call. RRULE expansion is also out of scope: stored verbatim on the event, never expanded. Recurrence + multi-platform fan-out are the natural next steps when the model needs to grow.

**UI is vanilla JS SPA — no framework, no build step.** `index.html` is the shell; views mount in `#app-root` via `fb.router.register("#/path", "tag-name", { label, icon })`. **Views use light DOM** (so `app.css` applies); **components use Shadow DOM** (style isolation). Theme via CSS custom props on `:root` (`--accent`, `--accent-warm`, `--danger`, `--glass`, `--border`, `--text-muted`). System components prefixed `fb-`; mods use `usr_` in `fishbowl-mods/components/`. `fb.icons.register(name, path)` extends icons. `/login` and `/setup` stay server-rendered. Component spec: `docs/superpowers/specs/2026-04-19-ui-foundation-design.md`.

**Context is URL-driven** (personal vs space workspace). `#/notes` = personal, `#/space/<slug>/notes` = space. `fb.context` in `/js/lib/context.js` parses the hash, exposes `get/endpoint/hashFor/set`, and emits `fb:context-changed` on every switch. `fb.api.{notes,tags,todos,search}` route through `fb.context.endpoint(path)` so the same wrapper hits `/api/v1/...` or `/api/v1/spaces/<slug>/...` automatically — no mirror client code. The router strips the space prefix for view lookup (`fb.router.currentResource()`) so one view registration serves both workspaces. Hrefs that should be sticky across contexts (nav items, hub tiles, brand) wrap through `fb.context.hashFor()`. Switcher: `<fb-context-switcher slot="context">` inside `<fb-nav>`; the ribbon exposes a dedicated `.context` slot that `renderToolbar()` never touches (so the switcher survives per-view toolbar paints). Space context tints the switcher with `--accent-warm` so edits to shared data are unmissable. `fb.tags` cache invalidates on `fb:context-changed`.

**UI smoke test (`Fishbowl.Ui.Tests`)** launches `Fishbowl.Host` as a real subprocess on a free port for Playwright (not `TestServer`). A gated bypass (`FISHBOWL_PLAYWRIGHT_TEST` env + `Testing` environment) injects a test user. **Never set `FISHBOWL_PLAYWRIGHT_TEST` outside that fixture.**

**MCP surface** at `POST /mcp` — JSON-RPC 2.0 over Streamable HTTP, Bearer-auth only. Eight tools in `Fishbowl.Mcp.Tools/*` grouped by domain: notes (`search_memory`, `remember`, `get_memory`, `update_memory`, `list_pending`), contacts (`list_contacts`, `find_contact`), events (`list_events`). Each implements `IMcpTool` with a `RequiredScope`; `ToolRegistry` lists them for `tools/list`. MCP writes pass `NoteSource.Mcp` → `NoteRepository.ApplySourceTags` auto-adds `source:mcp` + `review:pending`. Human edits (cookie path) strip `review:pending` (approval by editing). **Secret-strip invariant:** every note response runs through `SecretStripper.StripNote` — `::secret`…`::end` blocks and `content_secret` blobs must never cross the MCP wire. Enforced by `SecretStripInvariantTests`.

**Hybrid search** (`HybridSearchService` in `Fishbowl.Data.Search`) blends sqlite-vec cosine distance (70%) with FTS5 bm25 (30%), each min-max normalised over a 50-candidate pool. `search_memory` tool always calls it; a `degraded: true` flag surfaces on the response when the embedding model isn't ready yet and ranking falls back to FTS-only. FTS query tokens are split on non-alphanumeric then prefix-matched with `AND` — matches how FTS5's default tokenizer indexes hyphenated identifiers. Lives in `Fishbowl.Data.Search` (not `Fishbowl.Search`) because it needs `DatabaseFactory`, and the dep direction forbids `Fishbowl.Search → Fishbowl.Data`; same reason `SqliteVecLoader` is in `Fishbowl.Data`.

**Embeddings:** `MiniLmPipeline` (ONNX Runtime + `Microsoft.ML.Tokenizers.BertTokenizer`) produces 384-dim L2-normalised float vectors for `sentence-transformers/all-MiniLM-L6-v2`. `ModelDownloader` pulls `model.onnx` + `vocab.txt` from HuggingFace on first start, SHA-256-pinned for the LFS-stored model. `EmbeddingInitializer` (`IHostedService`) runs the download detached. Callers on the hot path catch `EmbeddingUnavailableException` and degrade — `NoteRepository.UpsertEmbeddingAsync` logs and continues, `HybridSearchService` flips to FTS-only. `IEmbeddingService` lives in `Fishbowl.Core.Search` so `NoteRepository` can depend on it without a reverse-dep into `Fishbowl.Search`.

**vec_notes sync.** User DB v4 adds `vec_notes` (sqlite-vec virtual table, `FLOAT[384]`). Every `NoteRepository` write embeds `title + stripped content + tags` and writes the blob in the same transaction as `notes` + `notes_fts`. sqlite-vec's vec0 doesn't honour `INSERT OR REPLACE` as a true replace — use **DELETE then INSERT** explicitly. On delete, remove from `vec_notes` BEFORE `notes` (same pattern as `notes_fts`). Text fed to the model is always secret-stripped — a vector built from secret content would let semantic search surface notes on hidden text, violating the same invariant as the MCP wire.

**`POST /api/v1/search/reindex`** (cookie-only) triggers `NoteRepository.ReEmbedAllAsync` — iterates every note in the resolved context, re-runs the embed+DELETE+INSERT in one transaction, returns `{ processed, failed }`. Bearer requests get 403. Mirrored at `/api/v1/spaces/<slug>/search/reindex` for the space workspace. Used on model upgrade or the first time embeddings become available for a pre-existing personal DB.

**`GET /api/v1/search?q=…&limit=…&includePending=…`** is the CONCEPT.md hybrid search over notes: `HybridSearchService` blends sqlite-vec cosine distance with FTS5 bm25 and returns ranked hits + a `degraded: true` flag when the embedding model isn't ready yet. Response shape matches the MCP `search_memory` tool so clients can swap transports. `limit` is clamped to 1–100. Scope: `read:notes`. Space variant at `/api/v1/spaces/<slug>/search`. Notes-only for now; contact-scoped search stays on `/api/v1/contacts/search` until a unified ranker exists.

**`GET /api/v1/export/db`** (cookie-only) streams the authenticated user's SQLite file as a download via SQLite's online backup API — safe under concurrent writes, no lock, no corruption. `Content-Type: application/vnd.sqlite3`, `Content-Disposition: attachment; filename="fishbowl-<userId>-<yyyyMMdd>.db"`. Bearer requests get 403 (wholesale DB export isn't an agent action). The space variant `/api/v1/spaces/<slug>/export/db` is **owner-only** (`CanDeleteSpace`), not just any member: walking off with the whole space DB file is a terminal action, on par with space deletion. Implementation in `ExportApi.cs`; backup routes through a temp file and buffers into memory for the response (personal DBs stay small).

**Events** live at `/api/v1/events` (personal) and `/api/v1/spaces/<slug>/events` (space). CONCEPT.md § Calendar — "A calendar that belongs to you." `Event` model carries `Title`/`Description`/`StartAt`/`EndAt`/`AllDay`/`RRule`/`Location`/`ReminderMinutes`/`ExternalId`/`ExternalSource` + ULID + created_by + timestamps; the schema is the original `events` table from user DB v1 so no migration was needed. Scopes: `read:events`, `write:events`. List takes optional `?from=…&to=…` as an ISO-8601 half-open range; the repo stores `start_at` as ISO-8601 so lexical string comparison gives the right temporal ordering. RRULE is stored verbatim — no recurrence expansion on read; the future scheduler fires expansions when firing reminders. `DeleteAsync` cascades the matching `reminders` rows (reminders FK events.id and are ephemeral). Read-only MCP via `list_events` (scope `read:events`) — supports an `upcoming_days` shortcut or an `from`+`to` ISO range. Write tools deliberately not exposed: agents scheduling on your calendar has sharper consequences than agents remembering a note. No UI wired.

**Contacts** live at `/api/v1/contacts` (personal) and `/api/v1/spaces/<slug>/contacts` (space). CONCEPT.md § Contacts: "Not an address book. A living record of the people who matter." `Contact` model carries `Name`/`Email`/`Phone`/`Notes`/`Archived` + standard ULID + timestamps. Storage: user/space DB schema v5 adds `contacts` + `contacts_fts`. No secret-strip layer — there's no encrypted column on contacts, hence nothing to strip. Scopes: `read:contacts`, `write:contacts`. `ContactRepository` mirrors the `NoteRepository` pattern (FTS rowid mapped via `(SELECT rowid FROM contacts WHERE id = @Id)`; delete FTS before the row). `SearchAsync` uses the same prefix-match-AND tokenizer as `HybridSearchService` so hyphenated queries don't get parsed as FTS5 NOT operators; exposed at `/api/v1/contacts/search?q=…` and over MCP as `find_contact`. `list_contacts` MCP tool does the plain listing. No UI wired yet — backend-only until the editor shape lands.

**Space-nested API shape.** Every resource the SPA shows in a workspace has a cookie-scoped personal path **and** a space-scoped nested path, and they share the handler logic (just a different `ContextRef`): notes, tags (CRUD + color + rename), todos (CRUD), contacts (CRUD, reject readonly writes), search/reindex, export/db (owner-only). Space routes live in `SpacesApi.cs`, go through `ResolveSpaceAsync` (validates membership + Bearer-context match), and reject `role == Readonly` on writes via `SpaceRoleExtensions.CanWrite()`. Bearer tokens bound to a space can only hit their own space's paths; a personal-scope token on a space URL is 403 even when the human behind it is a member — the token's context, not the user's membership, is the authoritative scope.

**Dev ports.** In Development the host binds **both** `https://localhost:7180` **and** `http://localhost:7181`, and `UseHttpsRedirection` is skipped. The HTTP port is for programmatic clients (Claude Code's MCP over HTTP, `curl`) that don't want to deal with the self-signed dev cert; the HTTPS port stays the primary URL for browser + logged-in flows. A dev-only request-trace middleware logs `>> METHOD /path auth=… accept=…` and `<< … status scheme=…` on `/mcp` + `/api/*` so you can see what an MCP client is actually sending. Production: both the HTTP bind and the trace logger are skipped by `app.Environment.IsDevelopment()` gates.

**Prod ports.** Production binding is driven by what's in `system.db`. With ACME configured (`Acme:Domains`/`Acme:Email`/`Acme:AcceptTos` all set), `Program.cs` binds `0.0.0.0:80` + `0.0.0.0:443` and `UseHttpsRedirection` is active. Without ACME — fresh install or LAN-only deployment — Program.cs binds **`0.0.0.0:80` HTTP-only** so the operator can reach `/setup` on first boot, and `UseHttpsRedirection` is skipped (nothing's listening on 443 to redirect to). If `urls` is set in configuration — via `ASPNETCORE_URLS` env var or `--urls` CLI arg, both feed the same key — the fallback skips and Kestrel uses those URLs (operator escape hatch for a non-80 port; also how `PlaywrightFixture` pins its tests to a free loopback port without hitting the prod default). The "post-ACME" → "post-restart-binds-443" transition is why /api/setup returns `restartRequired: true` when ACME fields change.

**Dev tools under `tools/`.** `mint-dev-key` issues an API key directly against `ApiKeyRepository` without a browser session — supports `--scopes`, `--context user|space`, `--context-id <slug>`; token on stdout, metadata on stderr. `reindex-dev` calls `NoteRepository.ReEmbedAllAsync` against the disk (bypasses the cookie-only HTTP endpoint). `seed-dev-data` populates notes/todos/contacts in a context for quick UI + MCP iteration; sentinels (`seed:dev` tag on notes, `[seed-dev] ` prefix on contacts/todos) make it idempotent, `--force` overrides. `init-space <slug>` is the per-space bootstrap: creates (or reuses) a space with the given slug, mints a space-scoped API key with all read/write scopes by default, prints the bearer on stdout + a status banner on stderr. Stays agnostic about who consumes the bearer — downstream agent-CLI wiring (credential storage, MCP config) lives in the consumer's docs, not Fishbowl's. `snapshot-data` hot-backs-up the whole data dir via SQLite's online backup API to `fishbowl-backups/snapshot-<ts>/` — safe under live writes, intended for cron'd operator runs (see tools/snapshot-data/README.md). All read `system.db` via the real `DatabaseFactory`, share exit codes, and `tools/` is outside the product solution. `.mcp.json` at repo root (gitignored) holds Claude Code's local MCP config pointing at `http://localhost:7181/mcp`; regenerate the token with `mint-dev-key`.

**Per-space agent integration.** Any agent CLI that wants its own Fishbowl memory namespace gets its own **space** — file-boundary isolation, role-based membership, space-scoped MCP routes. `tools/init-space <slug>` bootstraps the space plus a space-scoped key. The bearer token's `fishbowl_context_type=space` claim carries the scope; there is no `project_id` MCP tool argument and no `X-Project` header — the token *is* the scope. The host also serves `/s/<slug>` as a 302 to `/#/space/<slug>/notes`, a thin URL-alias convenience for downstream link templates that prefer not to construct the SPA hash route directly.

## Testing

- `WebApplicationFactory<Program>` requires `public partial class Program { }` at end of `Program.cs` — leave it.
- `TestAuthHandler` reads **`X-Test-User-Id`** and synthesizes both `NameIdentifier` and `fishbowl_user_id`. Use this for any auth'd endpoint test — never mock Google OAuth.
- Fresh temp data dir per fixture, override `DatabaseFactory` singleton, **call `SqliteConnection.ClearAllPools()` before deleting** (Windows holds the file open otherwise).
- `Testing` env suppresses `StartupBranding` — don't add console output that assumes a TTY.

## Conventions

- **Dapper snake_case via `DapperConventions.Install()`** in `DatabaseFactory` static ctor — `created_at` → `CreatedAt` works automatically. `JsonTagsHandler` handles `List<string>` ↔ JSON for `notes.tags`. Use `QueryAsync<T>`, never `QueryAsync<dynamic>` with manual mappers.
- **FTS5 + vec_notes must stay synced.** `notes_fts.rowid` maps to `notes.rowid` via `(SELECT rowid FROM notes WHERE id = @Id)`. On delete, remove from `vec_notes` AND `notes_fts` BEFORE `notes`. Tags are space-joined string (not JSON).
- **Logging via `ILogger<T>?` defaulting to `NullLogger<T>.Instance`** so tests can construct objects directly. **Never log PII** (email, name, content, secrets, tokens). Sinks: console always, plus rolling daily file at `fishbowl-data/logs/host-{yyyy-MM-dd}.log` (Serilog) — file sink suppressed in `Testing` env so smoke fixtures don't accumulate temp artefacts. Retention + plain/JSON format read from `system.db` (`Logging:RetentionDays`, `Logging:Format`) via `BootConfig.LoadLogging` at boot; defaults are 7 days + plain text. Changing either needs a host restart (acceptable — ops don't retune logging hot).
- SQLite `DateTime` stored ISO-8601 (`.ToString("o")`); booleans as `INTEGER 0/1`; IDs are ULIDs.
- Secrets use `::secret` markdown block + separate `content_secret BLOB` (client-encrypted). **Never include secret content in FTS, embeddings, or chat responses** — non-negotiable; enforced by `SecretStripper` on every MCP return path.
- **System tags** carry three flags (`is_system`, `user_assignable`, `user_removable`) — set in `Fishbowl.Core.Util.SystemTags.Seeds`. Current seeds: `review:pending` (removable by user), `source:mcp` (locked). Rename/delete of `is_system=1` rows rejected in `TagRepository`.
- Modding rule: "disk file wins, else default" — uniform across components/styles/scripts/templates/plugins. No registration manifests or whitelists.

## CI

`ci.yml` runs on push to master and PRs (Linux + Windows): `dotnet format --verify-no-changes`, `dotnet build`, `dotnet test`. `release.yml` on `v*` tag publishes per-RID `Fishbowl-{version}-{rid}.zip` artefacts (each containing an `app/` directory with the self-contained single-file binary) for `win-x64`, `linux-x64`, `osx-x64`, `osx-arm64`.

## Husky launcher

The host attaches to [Husky](https://github.com/chloe-dream/husky) when the launcher hosts it (`HuskyClient.AttachIfHostedAsync` returns `null` under `dotnet run` / debugger, so dev is unaffected). Husky-driven shutdown forwards to `app.StopAsync(ct)` so hosted services (Discord bot, embedding initializer, ACME renewal) drain cleanly before the binary swap. End users run `Husky --repo chloe-dream/the-fishbowl --asset 'Fishbowl-{version}-<rid>.zip'`; Husky reads `husky.config.json` from the repo root for `name` + `executable` + timing knobs (currently Windows-pathed; Linux/Mac users override `executable` in their local config). Husky preserves anything outside the update package, so `app/fishbowl-data/` survives upgrades.
